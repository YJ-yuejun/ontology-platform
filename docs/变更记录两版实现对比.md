# 变更记录「记录 ↔ 资源」两版实现对比

对比对象：

| 代号 | 位置 | 实现时间 |
|---|---|---|
| **A · 运行副本版** | `/Users/yuejun/Documents/智能体平台/ontology-studio-manual` | 14:07–14:39（已 build 进 `dist`，`:8021` 正在提供） |
| **B · 分支版** | `/Users/yuejun/work/project/ontology-studio-manual-branch` | 本次修复 |

> 两版**功能等价**（都能从变更记录跳到资源、再跳回原记录），但设计取舍不同。下面只列差异，不做取舍判断，最后一节是供参考的互补建议。
>
> 差异集中在 `frontend/src/pages/ActivityLog.jsx`、`ActivityLog.css`；`historyNavigation.js` 只有 B 有改动。

## 1. 列表与详情的摘要

| | A · 运行副本版 | B · 分支版 |
|---|---|---|
| 摘要来源 | 新增 `changeSummary(item)`，三级优先：① 字段级差异（支持 `field.details` 嵌套说明）② 新增/删除生成"新增 对象类型「合同」" ③ 回落到原文 | 直接渲染 `mvc_chg_content` 原文（`contentParts` 逐行） |
| 列表列 | 用 `changeSummary` | 用原文 |
| 超长处理 | 超 2 项折叠为"… 等 N 项变化" | 无折叠，整段截断显示 |

**差异影响**：A 的列表和详情摘要一致，且能把"改了哪几个字段"直接说清楚；B 在列表里只能看到后端写入的那句文本。

## 2. 详情面板结构

| | A · 运行副本版 | B · 分支版 |
|---|---|---|
| 主变更块 | 新增「本次变更」区块（`.history-primary-change`）置顶 | 无，直接从「变更内容」开始 |
| 字段差异 | 除「修改前/修改后」外，额外渲染 `field.details` 为 `.history-nested-change` 说明行 | 只有「修改前/修改后」 |
| 原文位置 | 仅当摘要 ≠ 原文时，额外显示「原始操作描述」 | 固定显示「变更内容」 |

## 3. 「打开该资源」按钮

| | A · 运行副本版 | B · 分支版 |
|---|---|---|
| 形态 | 全宽主按钮：`前往当前资源详情` + 副文案 `可查看或编辑` | inline 按钮：`打开该资源` |
| 图标 | `ArrowUpRight` | `ExternalLink` |
| **删除类记录** | **不显示按钮**，改为文案"该资源已删除，不能返回当前资源详情。" | 仍显示按钮（跳到接收端后由 `not_found` 弹回，多一次跳转） |
| 无页面资源 | 统一文案"这类历史记录暂无可定位的资源详情页。" | 用 `UNDESTINED_RESOURCE_TYPES` 白名单**区分两种原因**：旧版资源（对象类型组/共享属性/提案/建模证据/属性）vs 记录没有资源 ID |

## 4. 资源不存在时的提示

| | A · 运行副本版 | B · 分支版 |
|---|---|---|
| 样式 | 黄色条 `.history-navigation-note` | 蓝色条 `.history-resource-gone` |
| 可关闭 | 否 | 是（"知道了"按钮，从 URL 移除 `not_found`） |
| 文案 | "该资源当前不存在，无法打开详情或编辑；历史记录仍可在这里查看。" | "该资源已不存在或不属于当前本体，已退回变更记录；历史记录仍然保留。" |

## 5. 从 URL 恢复现场

| | A · 运行副本版 | B · 分支版 |
|---|---|---|
| 初值 | `requestedRecordId` / `page` / `page_size` 作为 `useState` 初值 | 同左，但抽成 `returnRecordId` / `returnPage` / `returnPageSize` 命名常量 |
| 重置 | 一个 effect：`[activeId, resourceType, resourceId]` | 同一个 effect，额外带了"不跟随 `record_id` 变化以免打断用户当前选择"的注释 |
| 数据加载后 | 当前选中不在本页时，**优先回落到 `requestedRecordId`**，再回落到第一条 | 直接回落到第一条 |

**差异影响**：A 在"记录不在当前页"时更可能仍然选中目标记录。

## 9. 供参考的互补建议（不是结论）

如果最终想取两者之长，可以以 **A 为基座**，把 B 独有的三点补进去：

1. **对删除类记录**：A 已经做对了（隐藏按钮）——保留 A。
2. **对无页面资源的说明**：把 B 的 `UNDESTINED_RESOURCE_TYPES` 白名单和"旧版资源 / 无资源 ID"两种文案搬过去，比 A 的统一文案更可解释。
3. **路径表**：把 B 的 `link_instance`、`version` 两条补进 `RESOURCE_PATHS`。
4. **`not_found` 可关闭**：B 的做法更友好，但 A 的不可关闭更"强提示"，取决于产品偏好。
5. **`logic_definition` 显示名**：A 的「规则」与 `business_rule` 合并成一个标签，B 保留「规则与函数（旧）」——注意这会影响资源类型下拉的可选项数量，需与后端 `repository.py:1573` 的别名映射保持一致。
