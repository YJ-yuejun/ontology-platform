# 本体建模中心：一期与二期实施计划

## 产品目标

在现有智能体平台内建设 Foundry 式企业业务语义层，使业务人员、应用和 Agent 面对稳定的对象、关系、规则与 Action，而不是直接理解底层表结构。

## 当前原型状态（v1.9）

- 多本体目录、页面内切换和独立命名空间已实现。
- 分类口径已经收敛为“本体 → 业务域 → 主题域 → 对象类型”。
- 对象类型组、共享属性已退出产品；接口保持独立资源。
- 对象、属性、接口、关系、数据源、映射、实例、规则、Action、能力、权限、场景、版本和审计均有可交互原型。
- 业务场景使用真实资源引用组装，数据源由映射推导；执行步骤支持生成、编辑、排序、失败策略与人工确认。
- 智能构建覆盖新建与更新两种模式，支持文件证据、多轮分析、Proposal、人工评审、合并、校验与发布。
- 管网 15 Sheet 模板和采购财务本体均已内置并纳入回归保护。

## 一期：可用的本体建模与治理底座

| 能力域 | 研发范围 | 验收标准 |
|---|---|---|
| 本体容器 | 创建、修改、切换、归档、命名空间 | 多本体资源严格隔离，当前本体可在页面内切换 |
| 分类 | 业务域、主题域、对象直接归属 | 引用完整；存在下级对象时禁止删除主题域 |
| 语义模型 | 对象、属性、接口、关系、图谱 | CRUD 完整；唯一主键、标题、接口契约、关系端点可校验 |
| 数据接入 | 数据源登记、对象/属性/关系映射、样例测试 | 引用受控，主键覆盖率和关系匹配率可验证 |
| 运行数据 | 对象实例、实例关系、同步和质量状态 | 可按业务键查询并沿关系穿透 |
| 逻辑与行动 | 规则/函数、Action、系统能力、执行映射 | 规则可测试；Action 有输入、前置条件、输出、失败策略和审计要求 |
| 业务场景 | 入口、触发、路径、数据映射、规则、Action、审批、输出、验收与步骤编排 | 执行图引用受治理资源，顺序连续，写动作需要人工确认，运行轨迹可审计 |
| 治理发布 | 统一变更日志、评审状态机、不可变发布版本 | 不可越级发布；变更与版本均可追溯 |
| 权限 | 本体、对象、属性、实例、Action 级策略 | Agent 不获得超过当前用户的权限 |
| 模板导入 | 15 Sheet 文件预检、引用解析、错误报告、幂等导入 | 管网模板可重复导入且结果一致，错误能定位到 Sheet/行/字段 |
| 智能构建 | 新建/更新任务、Evidence、Proposal、Diff、人工决策 | AI 无正式模型直写权限；结果可追溯、可驳回、可重放 |
| 产品体验 | 全中文、结构化表单、导航折叠、桌面响应式 | 不要求业务用户手写 JSON；1280/1440/1920 可用 |

一期完成门槛：即使关闭大模型，系统仍能可靠完成手工建模、数据映射、实例查看、校验、评审和发布；启用模型后只增加提案效率，不改变治理边界。

## 二期：企业生产化与 Agent Runtime

| 任务 | 建议周期 | 完成标准 |
|---|---:|---|
| 版本化元数据与协作 | 2–3 周 | 分支、并发编辑、Diff、冲突解决、回滚可用 |
| 连接器和增量同步 | 3–4 周 | 数据库、API、消息、文件统一接入，可观测、可重放 |
| 解析与证据服务 | 2–3 周 | 大文件异步解析，页码/单元格证据定位，Evidence Set 版本化 |
| 智能对齐与迁移 | 3 周 | 同义合并、资源复用、Breaking Change 识别和迁移计划 |
| 企业权限与策略 | 3 周 | 对象、属性、实例和 Action 细粒度授权，与身份系统联动 |
| Action 执行网关 | 3–4 周 | 审批、确认、幂等、超时、重试、熔断、补偿、人工接管和审计 |
| Agent Runtime | 3–4 周 | 本体工具发现、查询计划、关系穿透、规则调用、受控执行 |
| 评测和运营 | 持续 | Proposal 接受率、查询正确率、Action 成功率和风险拦截率可量化 |

## 关键依赖

```text
文件 / 数据库 / API
       ↓
Evidence Set → Ontology Proposal → Diff / Review → Working State → Validate / Publish
                                                              ↓
Data Mapping → Object Runtime → Rule / Function → Action Gateway → Agent Runtime
```

## 不变原则

1. AI 生成候选变更，不生成无需审核的事实。
2. Schema、Mapping、Instance 分层管理。
3. 规则、权限和业务写入走确定性执行链路。
4. Action 是受治理业务能力，不是任意数据库写入。
5. 多本体用于安全、组织、生命周期和协作边界，不按每个业务域机械拆分。
6. 业务域与主题域负责分类，接口负责契约，业务场景负责横向业务过程，三者不混用。
