# 本体质检与本体对比改造记录

产品方向：**去掉"版本"概念**。质检改成对话优先，对比改成选本体。

## 1. 本体质检：对话优先 + 报告侧边滑出

**改造前**：左边对话、右边常驻报告面板；必须点右上角"运行质检"；`run_quality()` 没有范围参数，永远全量查 9 项。

**改造后**：

- 页面主体只有一个**对话区**，报告不再常驻。
- 对话区顶部是**范围引导**：`全部质检` + 9 个检查维度 chip，可多选；不选即全部。运行按钮文案跟着范围变（`运行质检 · 已选 N 项维度`）。
- 点运行后**报告从右侧自动滑出**（520px 抽屉，`transform` 过渡），可点右上角收起，也可用页头的「查看质检报告」重新打开。
- 没出报告时，对话会先引导确认范围；已有报告时可以直接追问。

### 范围参数

| 层 | 改动 |
|---|---|
| `repository.validate_ontology` | 每个 check 增加 `key`（供按维度裁剪），保留 `name` 作为人类可读标签 |
| `governance_insights.QUALITY_DIMENSIONS` | 新增 9 个维度的 key / 标签 / 说明，作为唯一事实来源 |
| `_quality_payload(oid, scope)` | 按 scope 同时裁剪 `checks` 与 `issues`；`component` → 维度 key 的映射见 `_COMPONENT_TO_DIMENSION` |
| `run_quality(oid, scope)` | 接受 scope，写入 `report.scope_keys`；`version_label` 列现在承载**质检范围**（如"全部维度"、"对象主键与标题属性、关系端点与状态一致"），不再表达版本 |
| `GET /api/quality-dimensions` | 返回 9 个维度，供前端做引导 |
| `POST /api/ontologies/{id}/quality-runs` | body 可选 `{scope: [...]}`；省略或空数组＝全部维度（旧调用不传 body 仍然可用） |

9 个维度：`object_type`、`link_type`、`action`、`business_rule`、`interface`、`classification`、`ontology`、`data_mapping`、`logic_definition`。

## 2. 本体对比：选本体，不选版本

**改造前**：两个下拉都是**发布版本 / 当前工作状态**，且 `compare_versions()` 的 SQL 带 `WHERE ontology_id=?`——只能在同一个本体内部比。

**改造后**：两个下拉是**基准本体 / 对比本体**，调用新的跨本体接口。

### 为什么不能直接用旧的对比逻辑

复制出来的分支本体里，**所有资源都是新 UUID**。旧逻辑按 UUID 匹配，实测把本体复制一份后对比：

| 匹配方式 | 复制后对比的结果 |
|---|---|
| 旧：UUID 匹配 | **62 条假差异**（31 新增 + 31 删除），等于把整个本体报成删掉重建 |
| 新：业务稳定键匹配 | **0 条差异** ✅ |

### 新逻辑

- `_stable_index(snapshot)`：对象类型 / 接口 / 关系类型 / 业务规则 / 动作类型用 **`name`**；业务域 / 主题域与全部企业资源用 **`code`**。
- `_normalize_references`：把 `subject_domain_id`、`business_domain_id`、`source_object_type_id`、`target_object_type_id`、`interface_ids` 从 UUID 归一化成对侧的稳定标识；属性里的 `shared_property_id` 置空（运行时引用，跨本体无意义）。**不做这步的话，每条关系都会被判成"已修改"。**
- 端点：`POST /api/ontologies/{id}/compare-with`（body `{other_id}`）与 `/compare-with/chat`。
- 对比结论与解读文案由 `_diff_answer()` 统一生成，`compare_versions` 与新接口共用。

**注意**：旧的 `/version-compare` 端点与 `ReleaseSnapshot`、`Governance` 的发布/评审流程**本次未删除**，本次只改了对比页的入口。要彻底去掉版本机制（含 `ontology_releases`、`/publish`、`/review/*`）需要单独一步，且会波及图谱版本下拉、只读快照页与质检指纹。

## 3. 顺带修掉的问题

- `GovernanceInsightChat` 增加 `guide` / `headerExtra` 插槽（供质检页放范围引导），并把 `.gi-chat-panel` 从固定 3 行 grid 改成 flex 列，这样有/无引导时布局都正确。
- 报告抽屉表头在 520px 宽度下会把"质检报告"挤成竖排，已改为可换行 + 标题不折行。
