## 平台数据与模板的关系

### 1. 原始值与运行值分层

`template_records` 是不可丢失的来源层；对象、关系、Action、数据映射等业务表是可查询、可执行的规范化层。两者通过 `normalized_ref_type` 和 `normalized_ref_id` 关联。后续重新导入或升级字段时，可以从来源行重放，不依赖页面上当前显示的文本。

### 2. 对象与属性

对象类型保留模板的中文名称、对象类别、业务域、业务定义、主键、生命周期、状态属性、负责人、来源系统、核心/事件/需行动和建模状态。对象 API 名称（例如 `TransportTask`）只作为程序稳定引用。

属性 P-001～P-010 已写入对象属性 JSON：`属性类别`、`唯一`、`来源系统`、`来源字段`、`更新频率`、`转换规则`、`质量要求`、`状态`均可从 API 查询。平台为没有在 03 Sheet 单列属性、但实例必须具备的主键/标题字段增加了“平台补齐”字段，并在属性来源元数据中标明。

### 3. 关系与图谱

04 Sheet 是运行时关系事实，14 Sheet 是可选展示数据。两者都保留，但图谱接口只从关系类型生成边，避免展示表中的方向错误影响 Agent 穿透。模板 API 名称、起点键、终点键、来源系统和版本都在关系元数据中保留。

### 4. 数据源、映射与执行能力

数据映射使用 `DS-xxx` 作为可选择的数据源编码；`M-001`～`M-004` 的对象/属性/关系目标、来源表/接口、字段、关联键、转换、质量、更新方式和责任人均在 payload 中保存。Action 不直接写接口地址，而是通过 `AX-xxx → I-xxx` 绑定到受治理接口能力，满足本体契约与执行系统解耦的设计。

## 已保留的显式语义修复

这些修复没有覆盖原始值，均可在 `template_records.issue_note` 或对应资源的 `template_raw` 中复核：

1. 03 Sheet 的 P-007/P-008 使用 `OBJ0004`，但对象名称为“管段”；平台按业务名称绑定 PipeSegment，并保留原始对象类型 ID。
2. 14 Sheet 的关系图方向与 04 Sheet 不完全一致；平台以 04 Sheet 的起点、终点和方向为运行事实。
3. A-002 的作用对象写作“阀门”，模板对象类型只有“设备”；平台绑定 Equipment，并保存 `target_role=阀门`。
4. SCN-002 的关键关系包含“运输任务—经过—管段”，但主要对象列漏写管段；规范化场景补齐关系端点，原始主要对象列不变。
