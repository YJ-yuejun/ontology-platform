# 发布审核与已发布搜索问数 · 调研与 MVP 设计

> 目标：让“发布”成为本体对外提供搜索、智能问数的唯一可信边界；同时明确审核、确认、发布和多账号要做到什么程度。

| 项目 | 内容 |
|---|---|
| 文档性质 | 调研 + 产品/架构设计 |
| 适用功能 | 本体的搜索、智能问数、审核、确认、发布 |
| 文档状态 | 待确认 |
| 更新日期 | 2026-10-26 |

## 1. 结论先行

### 1.1 当前不是“完全没有发布”

代码里已经有发布骨架：

- 本体状态：`设计中 → 待评审 → 评审通过 → 已发布`
- 发布前有模型校验、本体质检、待发布变更清单
- 有不可变发布快照 `ontology_releases` 和只读历史版本页
- 有发布影响、兼容性判断、版本升级、发布记录

但当前缺少三件关键东西：

1. **发布没有成为搜索和问数的数据边界**：搜索仍可能读工作状态/实例；发布快照只包含语义资源和数据映射，不包含可搜索的对象记录。
2. **审核没有真实身份和权限**：当前审计主体默认 `manual-admin`，没有多账号、角色、评审人、发布人分离。
3. **发布没有“数据发布/索引发布”阶段**：语义发布成功，不等于对象记录可被搜索；需要独立的“已发布搜索索引”。

所以正确说法是：

> 已有语义发布流程，但没有真正的“已发布数据视图 + 搜索索引 + 权限闭环”。

### 1.2 建议做到什么程度

建议采用 **MVP 先闭环，权限后增强** 的路线：

**MVP（本轮建议）**

- 一条完整发布链：工作状态 → 提交评审 → 评审通过 → 发布语义版本 → 构建已发布索引 → 激活搜索版本
- 发布前检查：模型校验 + 本体质检 + **搜索属性映射覆盖率**
- 单评审人 + 单发布人；默认不允许提交人自审自发
- 发布记录、评审意见、拒绝原因、发布人、发布时间可追溯
- 已发布索引失败时，**不切换线上版本**，保留上一版可用
- 搜索只读“当前激活版本”的已发布索引
- 智能问数只读同一份索引，回答必须带对象类型、业务主键、发布版本等引用
- 多账号：至少区分 **建模人 / 评审人 / 发布人 / 只读用户**；生产接 SSO，不先自建密码体系

**暂不做**

- 多级会签、按资源逐项审批
- 行级/字段级权限（先按对象类型/角色控制）
- 实时增量索引、向量检索
- AI 自动执行写操作
- 跨本体联合问数

## 2. Palantir 的参考做法

Palantir 的 Ontology 不是“编辑后立即对所有人生效”，而是分支/提案/评审/合并的受控流程：

- **Global Branching / Ontology proposal**：在分支上修改，提案包含变更任务、评审、描述；通过评审后合并回主 Ontology。
- **资源保护**：受保护资源不能在主分支直接改，必须走分支和提案。
- **评审权限**：评审人需要 owner/editor 权限；提案创建者如果对变更资源有 owner/editor 权限，可以自审（最佳实践仍建议独立评审）。
- **Ontology 角色**：Owner / Editor / Viewer / Discoverer；Ontology 元数据权限和底层数据权限分开。
- **对象搜索**：对象后端提供搜索/过滤/聚合；权限在数据层和对象层生效；行级权限可通过 restricted view 控制。

参考：

- [Branching the ontology](https://www.palantir.com/docs/foundry/ontologies/branching-ontology)
- [Ontology proposals (Legacy)](https://www.palantir.com/docs/foundry/ontologies/ontology-branches-legacy)
- [Ontology permissions (Legacy)](https://www.palantir.com/docs/foundry/object-permissioning/ontology-permissions-legacy)
- [Ontology architecture](https://www.palantir.com/docs/foundry/object-backend/overview)
- [Restricted-view-backed object types](https://www.palantir.com/docs/foundry/object-permissioning/configuring-rv-access-controls)
- [Search Objects API](https://www.palantir.com/docs/foundry/api/v1/ontology-resources/objects/search)

我们不需要一次做成 Palantir 的 Global Branching；但“主版本不可直接改、提案评审、发布后不可变、权限分层”这四个原则应该保留。

## 3. 产品模型：两层发布

### 3.1 语义发布

发布内容：

- 对象类型、属性、关系和接口
- 动作、规则、权限策略
- 数据源、数据映射、业务场景
- 字典、分类、主题域等元数据

产出：

- 不可变语义版本 `release`
- 版本号、兼容性、发布说明、评审人、发布时间
- 只读历史版本

### 3.2 数据发布 / 索引发布

发布内容：

- 属于该语义版本的对象记录
- 只包含“可搜索属性”
- 每条记录带对象类型、主键、标题、搜索文本、来源、质量标记、权限标记

产出：

- 与该 `release` 绑定的搜索索引
- 索引状态：构建中 / 可用 / 失败 / 已过期
- 线上只切换 **可用索引**

### 3.3 激活指针

```text
ontology.active_release_id
ontology.active_index_id
```

- 搜索、问数只读 active index。
- 新版本发布失败，active 指针不切换。
- 历史版本保留，可回滚指针。
- 工作状态变更不自动影响 active 版本。

## 4. 发布生命周期

```text
draft（设计中）
  → submit_review（提交评审）
    → in_review（待评审）
      → approve（评审通过）
        → approved（待发布）
          → publish（发布语义版本）
            → indexing（构建已发布索引）
              → active（已发布并可用）
              → index_failed（索引失败，保持上一版 active）

in_review → reject → draft
approved → cancel → draft
active → rollback → previous active
active → derive → draft（派生新工作状态）
```

### 4.1 提交评审

必须满足：

- 有未发布变更。
- 模型校验通过。
- 本体质检通过且质检后模型未变化。
- **搜索属性映射覆盖检查通过**：
  - 对象类型必须配置标题属性/业务主键。
  - 标题属性与所有标记为 searchable 的属性，必须有已确认映射；否则阻断或明确列入“不可搜索属性”。
  - 关系映射不阻断基础搜索，但影响关系问数。
- 变更影响、兼容性、待核查场景已生成。
- 提交人、提交时间、变更说明已记录。

### 4.2 评审

评审人看到：

- 变更资源清单（新增/修改/删除）。
- 每个资源的字段级 diff。
- 影响范围：对象类型、关系、映射、场景。
- 兼容性：兼容 / 增量兼容 / 破坏性。
- 映射覆盖率与缺口。
- 质检结果。
- 评论、拒绝原因。

评审规则：

- 默认 **提交人不能审批自己的发布**。
- 破坏性变更建议要求 owner + reviewer 两人。
- 驳回必须填写原因；状态回到 draft，但保留评审记录。
- 通过后锁定本次发布内容，进入 approved；不能再改资源，需重新派生。

### 4.3 确认发布

发布人二次确认：

```text
版本号（主/次/修订）
发布说明
变更数量
影响对象/关系/映射/场景
质检结果
映射覆盖率
不可逆/兼容性提示
```

发布按钮不是“点一下直接上线”，而是：

```text
发布语义版本
  → 构建搜索索引
  → 校验索引
  → 切换 active 指针
  → 通知/审计
```

### 4.4 索引失败与回滚

- 语义版本可以已生成，但索引失败时，新版本不能成为 active。
- 线上继续使用上一版 active index。
- 失败状态、原因、重试入口可见。
- 回滚只切换 active 指针，不删除历史版本。
- 回滚需要发布人/owner 权限，并写审计。

## 5. 什么叫“已发布、已映射的本体记录”

搜索和问数只能返回满足全部条件的记录：

| 条件 | 规则 |
|---|---|
| 语义版本 | 对象类型存在于当前 active release |
| 对象记录 | 只读已发布数据索引，不读工作状态 |
| 记录状态 | `record_status = 有效`；停用/历史不返回 |
| 映射 | 标题属性和 searchable 属性有已确认映射 |
| 映射版本 | 使用 active release 中的映射版本，不使用工作状态新映射 |
| 权限 | 当前用户对对象类型/行有读权限 |
| 质量 | 质量失败记录默认排除；警告可返回并标记 |
| 索引 | 仅 active、可用、未过期索引 |

### 5.1 搜索属性

每个对象类型配置“搜索画像”：

- 标题属性（必选）
- 业务主键（必选）
- 可搜索属性（可选，多选）
- 可筛选属性（可选）
- 展示属性（结果卡）
- 关联对象标题（可选，后续）

未映射的 searchable 属性不能进入索引；发布评审中显示缺口。

### 5.2 记录不满足条件时

- 不在搜索结果中出现。
- 不进入 AI 问数上下文。
- 对象视图可以显示“该记录未进入已发布搜索索引”的原因。
- 不把工作状态记录混入已发布结果。

## 6. 搜索业务流

### 6.1 入口

- 全局搜索入口。
- 本体工作台/对象探索的“搜索已发布数据”。
- 搜索结果中的“问 AI”入口。

### 6.2 搜索页

```text
[当前本体] [已发布版本 vX.Y.Z] [索引可用]
[搜索框：标题 / 业务主键 / 属性值]
[对象类型] [业务域] [状态] [来源系统] [质量]
结果：
  对象类型 · 标题
  业务主键 · 对象类型 · 业务域
  匹配属性摘要
  更新时间 / 数据来源
  [打开对象] [问 AI]
```

- 默认只搜索 active release。
- 明确显示“已发布版本”与“索引时间”。
- 若工作状态有未发布变更，显示提示：“搜索结果不包含未发布变更”。
- 结果按相关度/更新时间排序。
- 支持键盘上下选择、Enter 打开。
- 无结果时提示调整关键词/筛选，不伪造结果。

### 6.3 搜索范围

MVP 支持：

- 标题、业务主键。
- 已映射的 searchable 属性。
- 对象类型、业务域、状态、来源系统筛选。
- 结果卡摘要。

后续：

- 关联对象标题/属性。
- 同义词、拼写纠错、向量召回。
- 保存搜索、订阅。

## 7. 智能问数业务流

### 7.1 定位

智能问数是**已发布数据的只读问答**，不是建模助手，也不是 SQL 控制台。

```text
自然语言问题
  → 识别意图（查记录 / 统计 / 分组 / 对比 / 关系）
  → 绑定 active release 的对象/属性/映射
  → 生成结构化查询计划
  → 权限过滤
  → 查已发布索引
  → 生成回答 + 引用
```

### 7.2 支持的问题类型（MVP）

| 类型 | 示例 |
|---|---|
| 查记录 | “付款申请里金额超过 100 万的记录有哪些？” |
| 计数 | “本月有效采购订单有多少？” |
| 分组 | “按供应商统计付款金额” |
| 对比 | “采购订单和付款申请的金额分布差异” |
| 关系 | “这个合同关联了哪些发票？” |
| 定义 | “付款申请的状态有哪些业务含义？” |

### 7.3 不支持 / 降级

- 跨本体联合查询。
- 任意 SQL 直查。
- 预测、归因、外部联网数据。
- 未发布对象/未映射属性。
- 权限范围外的数据。

降级：

- 问题不清楚 → 反问澄清。
- 对象/属性无法绑定 → 说明缺口，不猜测。
- 无数据 → 明确“已发布范围无匹配记录”。
- 统计问题 → 用聚合结果回答，不让模型“数”原始记录。

### 7.4 回答与引用

回答必须包含：

- 使用的对象类型和发布版本。
- 数据范围/筛选条件。
- 结果数量。
- 引用记录（标题 + 业务主键 + 对象类型）。
- 可展开的查询计划（“我查了什么”）。
- 数据时间/索引时间。

不允许：

- 引用不存在的记录。
- 把工作状态数据当已发布数据。
- 绕过权限返回记录。
- 用模型生成数字代替聚合查询。

### 7.5 问数入口

- 搜索页顶部“问 AI”。
- 对象探索页“问当前已发布数据”。
- 允许从搜索结果带入对象/记录作为上下文。
- 回答中可继续追问，沿用查询范围。
- 明确“只读”，不提供写操作。

## 8. 审核、确认、发布页面

### 8.1 发布中心

新增/强化：

```text
[当前版本 vX.Y.Z] [状态]
[待发布变更 N 项] [质检] [映射覆盖率]
[提交评审] / [评审通过] / [发布]
[评审人/发布人/时间]
[发布历史]
[索引状态]
```

### 8.2 评审页

- 变更 diff。
- 资源级评论。
- 通过/驳回。
- 评审人、时间、意见。
- 映射覆盖缺口。
- 质检报告。
- 破坏性变更提示。

### 8.3 发布确认页

- 版本升级选择。
- 发布说明。
- 变更摘要。
- 索引受影响对象类型/记录数估算。
- 索引构建中/成功/失败状态。
- 取消/确认。
- 发布后不可直接修改，只能派生新工作状态。

## 9. 多账号与权限

### 9.1 是否需要多账号

**需要。** 单账号无法形成真正的评审和发布控制：

- 提交人、评审人、发布人不能永远是同一个 `admin`。
- 审计记录无法区分责任。
- 搜索/问数需要按用户过滤数据。
- 生产环境必须支持人员离职、角色变更、最小权限。

### 9.2 最低角色模型

| 角色 | 能力 |
|---|---|
| 平台管理员 | 管理本体、账号/角色、系统配置 |
| 本体 Owner | 本体内全部资源、评审、发布、权限 |
| 本体 Editor | 编辑工作状态，提交评审；不能发布 |
| Reviewer | 查看 diff、评论、通过/驳回；不能发布 |
| Publisher | 确认发布、切换 active、回滚 |
| Analyst | 搜索、问数、只读对象视图 |
| Auditor | 只读审计/发布记录 |

建议至少保证：

- Editor ≠ Reviewer（默认）。
- Reviewer ≠ Publisher 可选；高风险要求分离。
- Analyst 只能读已发布版本。

### 9.3 认证方式

- 生产：企业 SSO（OIDC/SAML），按组织组映射角色；不自建密码。
- 私有化/无 SSO：本地账号 + 强密码哈希 + 会话 + 登录审计；作为临时方案。
- 原型演示：可提供“演示身份切换”（建模人/评审人/发布人），必须标注“仅演示，不是安全边界”。

### 9.4 数据权限

- 对象类型级读权限（MVP）。
- 行级/字段级权限后续。
- 搜索结果和 AI 检索都在服务端做权限过滤。
- 不允许把用户无权限的记录放入模型上下文、缓存或引用。
- 权限变化后，索引可保留，但查询时实时校验 ACL。

### 9.5 自审策略

- 默认：提交人不能审批自己的变更。
- 可配置：小团队/低风险允许自审，但必须显式开启并写审计。
- 破坏性变更：建议 owner + reviewer 双人。
- 发布人可以是 owner，但建议独立。

## 10. MVP 范围建议

### 10.1 本轮做

1. 发布状态机收口：draft → in_review → approved → indexing → active；失败/回滚。
2. 映射覆盖门禁：searchable 属性必须有已确认映射。
3. 已发布语义版本 + 已发布对象索引。
4. 搜索页：关键词、对象类型/业务域/状态/来源筛选、版本徽标、结果卡。
5. 智能问数：查记录/计数/分组/关系/定义；引用记录和发布版本；只读。
6. 角色最小集：Editor / Reviewer / Publisher / Analyst；SSO 或演示身份切换。
7. 审计：提交、评审、发布、索引、回滚。

### 10.2 暂不做

- 多级会签/逐资源审批。
- 行级/字段级权限。
- 实时同步和增量索引。
- 向量检索/语义召回。
- 任意 SQL、跨本体问数。
- AI 自动写操作。

### 10.3 判断标准

MVP 完成的标志：

> 一个未发布的工作状态变更，绝不会出现在搜索结果或问数回答中；  
> 一个未确认映射的属性，不会被当作已发布搜索字段；  
> 发布失败不会把线上切到坏索引；  
> 每个发布动作都能追到人、时间、变更和评审意见。

## 11. 主要风险

| 风险 | 处理 |
|---|---|
| 语义发布成功、索引失败 | 不切换 active；保留上一版；失败可重试 |
| 映射变更导致索引漂移 | 索引绑定 release；重新发布才生效 |
| AI 幻觉/编造记录 | 只返回检索结果；引用主键；无结果明确说无 |
| 权限泄漏 | 服务端 ACL 过滤；模型只接收过滤后的记录 |
| 审核流于形式 | 多账号、默认禁止自审、审计发布人 |
| 搜索数据量增长 | 先对象类型/时间范围限制；后续分页/聚合/索引服务 |
| 发布后仍被改 | 发布快照不可变；发布后派生新工作状态 |
