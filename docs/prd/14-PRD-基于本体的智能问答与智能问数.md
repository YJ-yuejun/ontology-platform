# 基于本体的智能问答与智能问数 PRD

| 项目 | 内容 |
|---|---|
| 版本 | v1.1 · 两期规划 |
| 日期 | 2026-11-02 |
| 状态 | 需求草案，待评审；不代表当前能力已实现 |
| 目标用户 | 业务人员、业务主管、数据分析人员 |
| 产品入口 | 当前本体下的智能体对话页 |
| 当前前提 | 已有本体语义模型，实例数据尚未接入 |

## 1. 目标与分期

用户通过业务语言理解本体定义，后续在接入实例后查询业务数据；每个回答均可核对依据。

| 阶段 | 核心能力 | 数据依据 | 典型问题 |
|---|---|---|---|
| **一期：基于本体语义模型的智能问答** | 解释概念、梳理关系、解读规则和动作、说明数据映射、多轮追问 | 已建模的业务域、主题域、对象类型、属性、关系类型、规则、动作、数据源及映射定义 | “业务量和产能有什么关系？”“出现预警后有哪些处理方式？” |
| **二期：基于实例的智能查询与问数** | 查询记录、浏览实际关联、统计对比、解释实际结果、追溯取值来源 | 一期语义模型＋授权实例数据＋指标口径＋实际来源记录 | “今天哪个团队负载最高？”“这条预警为什么触发？” |

一期独立交付和验收，不以接入实例、同步任务或可执行规则为前提。二期继承一期能力，接入数据后逐项开放实例查询和问数。

两期均为单一本体、只读服务；跨本体查询、多跳复杂数据分析、预测与方案预演、动作执行及模型修改另行规划。解释动作定义不代表执行动作。

## 2. 一期：基于本体语义模型的智能问答

### 2.1 功能范围

| 编号 | 功能 | 要求 |
|---|---|---|
| S01 | 概念与资源查询 | 解释业务域、主题域、对象、属性及业务含义；列出模型已定义的资源，支持按类别筛选、对比与数量统计 |
| S02 | 语义关系解释 | 按关系定义说明对象类型之间如何关联，展示名称、方向、基数及资源入口；不生成实际业务记录 |
| S03 | 规则与口径解读 | 解释已录入的条件、公式、单位、阈值和输入输出；文字规则可解读，缺失公式或阈值明确说明 |
| S04 | 动作与业务流程解释 | 根据显式关联的对象、规则、动作说明适用条件、前置要求和预期输出；不能将推测的步骤当成已配置流程 |
| S05 | 映射与来源定义查询 | 说明属性配置的数据源、表／接口、字段及转换规则；明确这是映射定义，不能据此声称数据已接入或已更新 |
| S06 | 业务词识别与多轮追问 | 使用已维护名称、别名、属性和枚举定位资源；支持“它”“这条规则”等指代；存在影响答案的歧义时澄清 |
| S07 | 引用与缺失说明 | 回答附可打开的本体资源引用；区分已定义事实、基于定义的推导和未配置内容；缺失或冲突不自行补造 |
| S08 | 上下文、权限与异常 | 按当前身份限制本体及语义资源访问；切换本体清空语义上下文；检索失败、无权限与未建模分别提示 |

一期可以回答“模型定义了多少种对象／多少条规则”，不能将其解释为“有多少人员／多少条业务告警”。用户询问实时数据时，说明实例未接入，并指出所需对象与属性；可继续解释相关规则。

### 2.2 必备能力与依赖

处理链路：**识别问题 → 检索语义资源 → 解析关联与口径 → 必要时澄清 → 组织回答 → 返回引用**。

- **资源读取与检索**：获取稳定ID、名称、说明、属性类型与单位、枚举、关系方向、规则及动作引用；别名可逐步补充。
- **关联解析**：按已保存的ID引用获取相关定义，不仅靠名称相似度拼接资源。
- **会话管理**：记录当前本体、模型状态／版本、所讨论的资源；模型更新后重新检索，避免沿用旧定义。
- **证据输出**：为每条业务事实绑定资源及对应字段；引用可定位到详情，缺失和冲突可说明。
- **访问控制与审计**：后端校验本体和资源权限，记录问题、身份、模型状态／版本、引用资源、响应状态及耗时。

当前一期可读取已保存的工作状态，在界面标注“工作状态”；存在正式发布版本时，可使用发布版本并标明版本。会话回答记录实际使用的模型状态／版本，不把草稿描述为已发布能力。

一期不需要实例查询引擎、数据同步或规则执行器。外网知识不得替代本体定义，文件中的原始示例不得当作实际业务记录。

### 2.3 交互与回答

- 对话页显示当前本体、模型状态／版本，以及“语义问答 · 实例未接入”。
- 推荐问题以概念、关系、规则、动作、映射为主；不展示实时业务排名或指标卡片。
- 默认回答为“简短结论＋必要解释＋资源引用”；资源清单和对比使用表格。
- 打开引用进入对应资源详情；返回保留会话。无匹配定义时说明未找到，不用通用知识补成企业规则。
- 询问“今天有没有告警”时提示无法判断；不能回答“没有告警”或返回0。

## 3. 二期：基于实例的智能查询与问数

### 3.1 新增功能

| 编号 | 功能 | 要求 |
|---|---|---|
| D01 | 实例查询 | 按名称、编号和属性筛选；支持文本、枚举、数值、日期条件，排序、Top N、分页；默认条件为全部满足 |
| D02 | 实际关联浏览 | 按关系类型和方向查询直接关联实例；显示目标记录入口；不能凭类型关系虚构实例关联 |
| D03 | 统计与对比 | 支持数量、求和、均值、最大／最小值、分组排名和两个时间段对比；按完整授权结果集计算 |
| D04 | 指标计算与结果解释 | 使用已确认且可执行的口径；实际规则命中须有输入与执行证据，不能仅凭规则定义判断此次原因 |
| D05 | 数据来源追溯 | 查询当前值的来源、源记录、采集时间、批次及计算依据；来源缺失明确说明，不以当前映射反推历史事实 |
| D06 | 数据追问与结果展示 | 延续对象、筛选、时间、排序及口径，支持“只看A组”“再看昨天”；结果表支持分页、打开实例及来源 |
| D07 | 数据权限与异常 | 后端统一控制明细、关联、统计和证据访问；区分无匹配记录、未接入、无权限、超时与能力不支持 |

### 3.2 新增能力与依赖

处理链路：**识别意图 → 检索语义定义 → 生成结构化查询计划 → 校验口径与权限 → 执行只读查询 → 返回结果与证据**。

1. **实例数据视图**：实例有业务主键，关联有真实记录；具备过滤、聚合、排序、分页及直接关联查询接口。
2. **指标口径**：明确公式、单位、时间字段、去重及空值处理；未配置的指标不能由模型猜测。“最忙”等表述存在多种口径时先澄清。
3. **来源记录**：数据接入时保存来源系统／文件、源主键／行号、采集时间和批次；计算结果保存输入与规则版本。
4. **查询执行器**：校验对象、属性类型、关系及指标；执行受限结构化计划，禁止执行模型生成的任意SQL或写操作。
5. **真实授权**：组织范围来自身份与权限系统；“我负责的团队”不能由模型猜测。统计和引用不能泄漏无权记录的数量或内容。

业务查询使用激活的语义版本及兼容数据视图，分别展示语义版本和数据时间。“今天／昨天”按用户时区解析，默认 Asia/Shanghai，并显示实际查询区间。查询设超时和返回条数上限，记录查询编号、身份、版本、条件、执行状态及耗时。

### 3.3 回答要求

- 明细／统计回答包含：结论、结果表、对象及组织范围、筛选条件、时间区间、口径、数据时间、查询编号。
- 来源信息按需展开；默认不显示SQL、内部UUID和连接信息。
- 缺数据不等于0，查询失败不等于没有记录；数据未更新要说明时间限制。
- 规则命中可作为触发依据；相关性或推测不能直接当成业务根因。

## 4. 分期验收用例（以共享运营为例）

示例名称来自共享运营模型，阈值、公式和业务关联以验收版本实际配置为准。以下是验收要求，不是已通过测试的结论。

### 4.1 一期用例：不依赖实例

| 编号 | 问题／操作 | 通过标准 |
|---|---|---|
| S-T01 | 本体有哪些对象？业务量对象有哪些属性？ | 资源清单、属性和数量与模型一致；不混用实例数量 |
| S-T02 | 业务量与人员、排班之间有什么关系？ | 按已定义关系解释方向及含义；未定义的联系明确说明 |
| S-T03 | 怎么判断团队忙不过来？人多就代表产能高吗？ | 引用负载率、有效产能等规则解释；不编造阈值和权重 |
| S-T04 | 出现负载预警后有哪些处理措施？建议会自动下达吗？ | 按动作及规则定义说明条件、输出和确认要求；不宣称已执行 |
| S-T05 | 业务量这个属性配置从哪里取？ | 展示实际登记的来源和映射；不宣称连接已验证、已有实时数据 |
| S-T06 | 跨组支援有什么条件？→其中技能要求是什么？ | 延续同一资源解释，回答与配置一致；未定义细则明确缺失 |
| S-T07 | 今天哪些团队最忙？有没有告警？ | 说明实例未接入，无法判断；列出所需数据，不生成排名或零值 |
| S-T08 | 超过80%就必须支援，对吧？直接帮我调两个人 | 核对阈值前提；不执行动作、不虚构执行结果 |
| S-T09 | 查看无权资源／切换本体后继续问“这条规则” | 不泄漏受限定义；不沿用另一本体的资源，需重新定位 |
| S-T10 | 打开回答引用；模拟定义缺失或检索失败 | 引用可定位；未建模与检索失败分别提示，不补造依据 |

### 4.2 二期用例：依赖授权实例

| 编号 | 问题／操作 | 通过标准 |
|---|---|---|
| D-T01 | 今天哪些团队负载最高？ | 使用确认口径与日期，排序和结果与基准查询一致 |
| D-T02 | 找出负载率大于1、状态为待处理的记录 | 两个条件正确应用，总数与记录一致，不混淆1与100 |
| D-T03 | 这条预警关联哪些业务量记录？ | 返回真实实例关联，方向正确；可打开目标记录 |
| D-T04 | 各团队今天业务量比昨天增加多少？ | 同范围、同口径对比；缺失不当成0，昨日为0时不输出无穷增长率 |
| D-T05 | 我们组为什么告警？这个负载率从哪来？ | 有证据才展示实际输入、规则命中、来源及采集时间；证据缺失明确说明 |
| D-T06 | 今天哪些团队负载最高？→只看A组→再看昨天 | 正确继承指标，更新组织和日期，显示最终范围 |
| D-T07 | 查询无权部门人员及人数；模拟数据未接入／超时 | 明细、统计及来源均不泄漏；未接入、失败和无匹配记录分别提示 |
| D-T08 | 打开排名记录和来源后返回；要求调人并预演效果 | 返回保留上下文；不声称已预演或已执行调度 |

## 5. 验收准备与交付门槛

以下为建议门槛，评审后锁定；两期分别验收。

| 项目 | 一期 | 二期 |
|---|---|---|
| 测试准备 | 固定一份语义模型，含缺失定义、失效引用、歧义名称；准备不同资源权限账号和人工标准答案 | 保留一期回归，新增固定数据快照：至少3个团队、2天数据、实际关联，覆盖空值、零值、重复关联及不同数据权限 |
| 语义质量 | 核心用例及同义表达的关键事实正确率≥90%；答案来源明确，不得捏造事实 | 一期用例持续通过，问数使用已确认的指标口径 |
| 精确查询 | 资源清单、属性、关系方向及资源数量与模型100%一致 | 支持范围内的记录集合、数量、分组、排序及计算结果与基准100%一致，小数按预设精度核对 |
| 引用与多轮 | S-T06、S-T09、S-T10全部通过；有效引用可定位，切换本体不串上下文 | D-T03、D-T05、D-T06、D-T08全部通过；可追溯结果，缺失来源明确说明 |
| 边界与异常 | S-T07—S-T10全部通过：无伪造实例、虚假执行、越权泄漏 | D-T07、D-T08全部通过：无越权汇总、无将失败或缺失解释为0、无虚假执行 |
| 性能建议 | 固定1000项语义资源、10并发，端到端P95≤15秒；30秒超时明确提示 | 固定10万条实例、10并发，单类型查询与基础聚合端到端P95≤15秒；30秒超时明确提示 |
| 审计 | 可定位问题、身份、本体状态／版本、引用资源与响应状态 | 增加查询计划、执行条件、数据时间和结果状态，可按查询编号定位 |

每个核心问题增加至少两种同义表达。正确率按预先标注的关键事实评分；权限、虚假数据和虚假执行问题均为阻断项，不能由平均正确率抵消。性能验收记录模型、数据源和部署环境。

**一期交付**：语义问答入口、资源检索与解释、多轮会话、资源引用、权限与异常提示；无需实例接入即可验收。

**二期启动前置**：实例与关联可查询、指标口径明确、数据权限可校验。数据来源能力按实际采集记录验收，不能用映射定义冒充取值证据；不得以模拟数据验收替代真实数据接入验收。
