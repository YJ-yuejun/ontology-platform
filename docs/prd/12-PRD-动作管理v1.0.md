| 项目 | 内容 |
|---|---|
| 路由 | `#/ontology/model/actions` |
| 模块 | 本体中心 → 本体模型 → 动作 |
| 版本 | v1.0，2026-10-30 |
| 状态 | 原型已实现 |

## 1. 目标与范围

动作是本体中可被业务触发、调用或编排的业务行为定义。本版本支持动作的建立、查询、编辑和删除，先保存清晰的业务定义，不执行公式、API 或审批流程。

用户需要配置以下字段，字段顺序就是页面的配置顺序：

| 顺序 | 字段 | 存储含义 | 控件 | 是否必填 |
|---:|---|---|---|---|
| 1 | 动作ID | 动作的稳定业务编号，保存到 `external_id` | 只读文本；新建显示“保存后由系统自动生成” | 系统生成 |
| 2 | 动作名称 | 动作名称，保存到 `display_name` | 文本 | 是 |
| 3 | 动作类型 | 动作业务分类，保存字典 code | `action_type` 字典下拉 | 是 |
| 4 | 作用对象 | 当前本体对象类型，选项同时显示对象名称和 external_id | 单选下拉，显示“对象名称 · 对象ID” | 是 |
| 5 | （关联值）作用对象ID | 选中对象对应的关联 ID | 不单独展示，由作用对象选择后自动保存 | 系统回写 |
| 6 | 输入参数 | 执行动作所需的业务参数名称 | 多行文本，使用顿号、逗号或换行分隔 | 否 |
| 7 | 触发条件 | 原“前置条件”的业务化名称 | 多行文本 | 否 |
| 8 | （关联值）触发规则ID | 选中规则的稳定 code 列表 | 不单独展示，由触发规则选择后自动保存 | 系统回写 |
| 9 | 触发规则 | 当前本体规则资源中的规则 | 紧凑多选下拉，显示“规则名称 · 规则ID” | 否 |
| 10 | 执行逻辑 | 动作如何执行的文字说明 | 多行文本 | 是 |
| 11 | 对象/属性变化 | 执行后的业务状态变化 | 多行文本 | 否 |
| 12 | 执行结果 | 业务上可观察的结果或输出 | 文本/多行文本 | 否 |
| 13 | 副作用/联动 | 通知、审计、回写等关联影响 | 多行文本 | 否 |
| 14 | 需审批 | 是否需要审批或授权 | 是/否下拉 | 是，默认否 |
| 15 | 责任人 | 动作业务负责人 | 文本 | 是，默认“示例负责人” |
| 16 | 资源使用状态 | 动作资源生命周期 | 启用/试验中/停用下拉 | 是，默认“试验中” |

字段“建模状态”（设计中/已确认）仍作为内部兼容字段保存，在详情中辅助展示；它与用户配置的“资源使用状态”不是同一个维度。

## 2. 资源关联规则

### 2.1 动作 ID与 API 名称

- 用户不手工填写动作 ID。
- 创建请求不提交 `external_id`，后端在当前本体事务内生成 `ACT-001`、`ACT-002` 等唯一编号；并发创建不会产生重复编号。
- 编辑时动作 ID只读，不能修改。
- 内部 API 名称由后端根据编号生成，例如 `action_act_001`，用户不需要看到或填写；历史 API 名称继续保留。

### 2.2 作用对象

- 表单只展示“作用对象”，选项来自当前本体 `/api/ontologies/{id}/object-types`。
- 用户选择对象名称后，前端提交 `target_object_type_id`；后端校验该对象属于当前本体。
- 对象 ID不作为独立输入框展示；对象选择项和详情统一显示“对象名称 · 对象 ID”。
- 不再让用户填写自由文本的作用对象称谓。历史数据中的 `target_role` 仅用于兼容展示，不覆盖原始记录。

### 2.3 触发规则

- 规则选项来自当前本体 `/api/ontologies/{id}/enterprise/logic-definitions`。
- 只显示规则资源，过滤 `category=函数/function` 的函数资源。
- 用户选择“触发规则”，支持多选；每个选项显示“规则名称 · 规则 code”。
- 前端提交 `trigger_rule_codes: string[]`，并可提交名称快照 `trigger_rules: string[]`用于展示；稳定关联以规则 code 为准。
- 后端校验每个规则 code 存在于当前本体，且不能引用函数、其他本体资源或重复 code。
- 规则被删除或停用后，历史动作保留原始 code，并在详情中显示“规则已失效/待处理”。

## 3. 页面行为

### 3.1 默认列表

进入页面、刷新页面或切换本体时，只显示动作列表，不默认展开右侧详情，也不自动选中第一条记录。

列表列为：动作名称/ID、动作类型、作用对象、触发规则、资源使用状态、更新时间。需审批在详情和编辑表单中配置，不在列表页单独展示。支持：

- 关键字搜索动作 ID、动作名称、内部 API 名称和触发规则；
- 按动作类型、作用对象和资源使用状态筛选；
- 分页和每页条数；筛选条件之间为 AND；
- 长文本通过悬浮提示查看完整内容；
- 点击“新建动作”直接打开配置表单。

### 3.2 详情展开与关闭

| 场景 | 行为 |
|---|---|
| 点击列表记录 | 展开右侧详情并显示全部业务字段 |
| 点击另一条记录 | 在同一详情面板切换记录 |
| 点击详情右上角 × | 收起详情，列表恢复全宽 |
| 关闭后再次点击记录 | 重新展开详情 |
| 筛选后当前记录不匹配 | 清除选择并关闭详情，不自动选择其他记录 |
| 新建或编辑保存 | 更新列表；不强制打开已关闭的详情 |

详情按四组展示：

1. 基础信息：动作 ID、动作名称、动作类型、作用对象（名称 · ID）；
2. 触发与输入：输入参数、触发条件、触发规则（名称 · ID，多条规则用“、”分隔）；
3. 执行定义：执行逻辑、对象/属性变化、执行结果、副作用/联动；
4. 管理信息：需审批、责任人、资源使用状态、建模状态。

详情保留编辑、删除、变更记录和关闭按钮；API 名称、创建修改人和时间放在“更多记录信息”折叠区。

## 4. 新建与编辑

表单按“基础信息 → 触发与输入 → 执行定义 → 管理信息”四组展示，默认全部展开。字段按第 1 节顺序排列，两列布局在窄屏自动变为单列。

- 动作 ID新建时只读显示生成提示；编辑时显示已有 ID且只读。
- 作用对象使用单选下拉，选项显示“对象名称 · 对象ID”；不再单独展示作用对象 ID输入框。
- 触发规则使用紧凑多选下拉，选项显示“规则名称 · 规则ID”；不再单独展示触发规则 ID输入框。
- 触发条件是前置条件的产品名称，后端继续兼容存储字段 `precondition_text`。
- 输入参数仍以业务名称文本配置，保存时转换成兼容的字符串参数结构；既有结构化参数元数据在未修改输入参数时保留。
- 创建和编辑只要求填写业务字段，不打开 API 地址、公式、参数 key、参数类型、结果 JSON 等技术字段。
- 未保存关闭需要确认；遮罩不关闭；保存中禁用表单。

## 5. 数据契约

### 5.1 创建请求示例

```json
{
  "name": "action_act_preview",
  "display_name": "生成排班调剂建议",
  "action_category": "business",
  "target_object_type_id": "<由作用对象回写>",
  "input_parameters_text": "预警等级、峰值时段",
  "precondition_text": "预警等级为预警或告警且高峰时段确定",
  "trigger_rule_codes": ["RULE-007"],
  "trigger_rules": ["排班调剂建议生成"],
  "execution_logic": "调用排班能力生成调剂建议",
  "object_effect": "生成排班调整建议",
  "result_text": "排班调整建议",
  "side_effects_text": "通知调度、记录审计",
  "approval_required": false,
  "owner": "示例负责人",
  "status": "experimental",
  "design_status": "draft",
  "action_type": "invoke",
  "definition_version": "v1.0",
  "definition_config": {"schema_version": 1, "definition_mode": "text"}
}
```

`external_id`不在创建请求中手工传入。后端返回完整动作记录时补齐 `external_id`、内部 API 名称、对象名称和审计字段。

### 5.2 字段映射

| 产品字段 | 原型/后端字段 |
|---|---|
| 动作 ID | `external_id` |
| 动作名称 | `display_name` |
| 动作类型 | `action_category`，保存字典 code |
| 作用对象 | `object_types.display_name`，由 `target_object_type_id` 解析 |
| 作用对象ID | `target_object_type_id` |
| 输入参数 | `input_parameters_text`；兼容结构为 `parameters` |
| 触发条件 | `precondition_text` |
| 触发规则ID | `trigger_rule_codes` |
| 触发规则 | `trigger_rules` 展示快照，优先由规则资源解析 |
| 执行逻辑 | `execution_logic` |
| 对象/属性变化 | `object_effect` |
| 执行结果 | `result_text`；兼容 `result_schema` |
| 副作用/联动 | `side_effects_text`；兼容 `side_effects` |
| 需审批 | `approval_required` |
| 责任人 | `owner` |
| 资源使用状态 | `status` |
| 建模状态 | `design_status` |

底层继续使用 `actions` 表和 `metadata` 扩展字段，不做破坏性数据库迁移。已有公式、API、结果结构、参数来源、原始模板和执行映射保留；本轮表单不会覆盖未展示的技术字段。

## 6. 校验与删除

- 动作名称在当前本体内唯一；已有动作的动作 ID和内部 API 名称不可修改。
- 动作类型必须是有效的 `action_type` 字典项；禁用字典项不能用于新建。
- 作用对象必须属于当前本体。
- 触发规则ID必须属于当前本体的规则资源，且不能是函数、重复或空值。
- 执行逻辑、动作名称、动作类型、作用对象、需审批、责任人和资源使用状态必填；其余业务说明字段可为空。
- 编辑携带 `expected_updated_at`，发现并发修改时阻止覆盖并要求刷新。
- `active` 动作不可直接删除；被业务场景、动作执行映射或权限策略引用的动作不能删除，返回引用信息。

## 7. 接口

继续复用：

- `GET /api/ontologies/{id}/actions`
- `POST /api/ontologies/{id}/actions`
- `GET /api/actions/{id}`
- `PUT /api/actions/{id}`
- `DELETE /api/actions/{id}`
- `GET /api/ontologies/{id}/object-types`
- `GET /api/ontologies/{id}/enterprise/logic-definitions`
- `GET /api/model-dictionaries/action_type`

本版本只保存动作定义，不执行动作；真实 API/公式/审批执行属于后续动作运行时模块。

## 8. 验收标准

- 默认进入动作页时详情关闭；点击记录可以展开，点击 × 可以收起。
- 新建动作不要求手填动作 ID、对象 ID或规则 ID；用户只选择动作资源，关联 ID由系统保存。
- 选择作用对象后请求携带对应 `target_object_type_id`，界面显示名称与对象 ID的组合文本。
- 选择多个触发规则后请求携带对应 `trigger_rule_codes`，后端拒绝跨本体或函数资源。
- 动作类型下拉来自 `action_type` 字典并保存 code。
- 创建成功后后端返回唯一 `ACT-xxx` 动作 ID，编辑时 ID不可修改。
- 详情完整展示本需求的 16 个业务字段，并区分资源使用状态和建模状态。
- 前端测试、生产构建和后端动作契约测试通过。
