## 1. 一句话定义

本体智能是嵌在本体建模工作台上的 AI 助手：它能读取当前本体、当前页面和用户选中的业务资源，回答问题、检查建模与映射问题，并起草可确认、可审计的修改提案。

它不是一个脱离本体的通用聊天窗口，也不是自动改模型的“黑盒执行器”。

## 2. 目标

1. 用户不用离开当前页面，就能针对对象、属性、关系、规则、映射等资源提问。
2. AI 始终知道“当前是哪个本体、在哪个页面、选中了什么”。
3. 先理解、再建议、最后确认：默认只读，写操作必须人工确认。
4. 从提问到追踪、从提案到执行，整个链路可解释、可取消、可追溯。
5. 全屏、浮窗、页面点选三种形态共享同一套会话和上下文，不丢状态。

## 3. 非目标

- 不替代完整的 BI 查询或 SQL 编辑器。
- 不自动执行未确认的写操作。
- 不展示模型隐藏推理过程。
- 不做多智能体自主协作。
- 不负责真实的数据同步、任务调度和业务系统写回。
- 不把整页 DOM、数据库连接串、密钥或未选中的敏感数据发送给模型。

## 4. 核心概念

| 概念 | 定义 |
|---|---|
| 本体 | 当前工作空间，所有会话、资源和权限都以本体为边界 |
| 会话 | 一段连续的多轮对话，包含消息、资源上下文和工具轨迹 |
| 资源上下文 | 用户选中的对象/属性/关系/规则/映射/实例/页面 |
| 页面范围 | 当前路由和页面标题，帮助 AI 理解用户正在看什么 |
| 工具轨迹 | AI 为了回答而调用的本体查询、校验、检索等步骤 |
| 回答 | 对事实、推断、建议的文本说明，可附带引用资源 |
| 提案 | AI 起草的写操作建议，确认前不产生实际修改 |
| 只读操作 | 解释、检查、查询、对比、起草建议 |
| 写操作 | 新建、修改、删除、执行动作、发布等会改变系统状态的操作 |
| 运行模式 | 真实模型运行，或原型中的演示降级模式 |

## 5. 产品形态与入口

### 5.1 全屏对话台

- 路由：`#/ontology/ai`。
- 左侧保留平台导航和本体导航；右侧为对话内容区。
- 适合长时间、多轮、需要查看历史和处理提案的工作。
- 顶部提供：当前本体、历史对话、新对话、收起为悬浮窗。

### 5.2 右下角浮窗

- 在除全屏对话台外的页面显示为圆形悬浮按钮。
- 点击展开为右下角面板，包含对话流、输入框和资源 Chip。
- 支持最大化到全屏对话台、收起浮窗。
- 适合“边看图/边看表边问”的短交互。

### 5.3 页面资源选择模式

- 从浮窗或对话台的资源面板进入。
- 页面顶部出现选择模式提示条。
- 点击页面上的对象、属性、关系等资源进行选中/取消。
- 完成后返回对话台/浮窗，资源以 Chip 形式带入。

### 5.4 资源页与图谱入口

- 对象、属性、关系、映射、规则等页面提供“问 AI”。
- 本体图谱支持右键对象/关系/画布。
- 所有入口最终都调用同一套“带入资源并打开浮窗”的动作，不允许每个页面各写一套对话。

| 对象 | 关键内容 |

| 消息 | 角色（用户/助手）、文本、资源、工具轨迹、运行模式、提案、错误状态 |
| 资源 | 类型、ID、显示名、父级、补充信息 |

| 审计记录 | 操作人、时间、会话、资源、提案、确认人、执行结果 |

## 8. 核心业务流

### 8.1 直接问当前本体

1. 用户进入本体智能。
2. 不选资源，直接输入问题。
3. 系统自动带入当前本体和当前页面范围。
4. AI 基于本体结构和已有会话回答。
5. 用户继续追问，或点击回答中的资源跳转。

适用：概览性问题、规则解释、概念查询。

### 8.2 页面选资源后提问

1. 用户点击资源面板的“去页面选择资源”。
2. 对话台收起为浮窗，页面进入选择模式。
3. 用户点击对象/属性/关系等资源，页面高亮。
4. 顶部选择条实时显示数量。
5. 点击“完成选择”，回到对话台/浮窗。
6. 用户输入问题或点击快捷动作。
7. 资源随问题进入上下文，AI 围绕资源回答。

适用：解释某个对象、检查某条关系、追查某个映射。

### 8.3 从资源页/图谱直接问 AI

1. 用户在对象属性页点击“问 AI”，或在图谱右键节点/关系选择“问 AI”。
2. 系统先确定资源，再打开右下角浮窗。
3. 浮窗带入资源 Chip 和预置 Prompt。
4. 用户确认后发送；不自动发送。
5. 资源页/图谱不跳转。

### 8.4 快捷动作

1. 选中资源后，输入区上方出现快捷动作。
2. 动作按资源类型变化。
3. 点击动作，等价于发送一个预置问题。
4. 动作执行期间按钮禁用。
5. 回答后仍保留资源，支持继续追问。

### 8.5 多轮追问

1. 用户发送后，消息进入消息流。
2. 资源默认保留，便于继续问。
3. AI 可引用上一轮资源；用户可移除或新增资源。
4. 用户可复制回答、重新生成、继续追问。

### 8.6 历史会话

1. 用户点击“历史对话”。
2. 抽屉按时间分组显示会话。
3. 搜索标题/首条消息。
4. 点击会话，恢复消息、最后一轮资源、会话 ID。
5. 切换会话不删除当前会话；新建对话也不删除历史。

### 8.7 收起/最大化

1. 全屏对话可“收起为悬浮窗”。
2. 收起后保留消息、资源、输入草稿、会话 ID。
3. 浮窗可最大化回全屏；状态不重置。
4. 只有切换本体才清空会话和资源。

### 8.8 提案确认与执行

1. 用户提出写操作请求，例如“给这个对象新增一个属性”。
2. AI 先理解资源与权限，生成提案，不直接写入。
3. 消息流出现提案卡。
4. 用户可查看影响、拒绝或确认。
5. 确认后弹出二次确认，展示目标、参数、风险、权限。
6. 用户确认后执行，显示成功/失败、运行 ID、审计入口。
7. 失败保留错误信息和重试入口；成功后允许继续追问。

### 8.9 错误与恢复

1. 请求失败，消息流追加错误提示。
2. 保留用户输入和资源。
3. 提供重试；用户可修改问题。
4. 不把失败轮次计入成功历史。
5. 模型降级时显示“演示降级模式”。

## 9. 交互状态机

```text
idle
  ├─ 选择资源 → selecting
  │                ├─ 完成/ Esc → idle（资源保留）
  │                └─ 切换本体 → idle（资源清空）
  └─ 发送 → sending
              ├─ 成功 → answered
              │           ├─ 只读回答 → 复制 / 重生成 / 继续问
              │           └─ 提案 → proposal
              │                         ├─ 查看影响 → proposal
              │                         ├─ 确认 → confirming → executing → executed
              │                         └─ 拒绝 → rejected
              ├─ 失败 → error → 重试 / 修改
              └─ 用户停止 → stopped → 重新发送

任意状态：
  切换本体 → idle（清空会话/资源）
  关闭浮窗 → 保持状态，重新打开恢复
  最大化/收起 → 保持状态
```

### 状态与界面反馈

| 状态 | 输入区 | 消息流 | 按钮 |
|---|---|---|---|
| idle | 可用 | 欢迎/消息 | 发送 |
| selecting | 禁用输入 | 选择提示 | 完成选择 |
| sending | 禁用/停止 | “正在读取…” | 停止 |
| answered | 可用 | 回答+轨迹 | 复制/重生成/追问 |
| proposal | 可用 | 提案卡 | 查看/确认/拒绝 |
| confirming | 禁用 | 确认弹窗 | 取消/确认 |
| executing | 禁用 | 执行中 | 取消（如支持） |
| executed | 可用 | 成功/失败+审计 | 查看审计/继续 |
| error | 可用 | 错误 | 重试 |
| stopped | 可用 | 已停止 | 重新发送 |

## 10. 上下文与资源规则

### 10.1 资源类型

对象、属性、关系、动作、规则、映射、实例、页面。

### 10.2 选择规则

- 最多 20 项。
- 重复资源自动去重。
- 页面选中状态与 Chip 双向同步。
- 切换本体：清空资源、消息、输入、思考/联网开关。
- 新建对话：清空资源、消息、输入，但保留历史。
- 加载历史：恢复该会话最后一轮用户消息携带的资源。
- 收起/展开：资源保留。
- 关闭浮窗：资源保留。

### 10.3 资源替换与追加

- “问 AI”从资源页/图谱进入时：**替换当前资源上下文**，保留会话消息。
- 页面选择模式：**追加/取消选择**。
- 资源面板：可单项移除、全部清空。
- 替换上下文时不自动发送；输入框预填对应问题。

### 10.4 页面范围

发送时带上当前路由和页面标题，用于判断用户所在工作场景。不读取整页 DOM，不读取未选中的敏感字段。

## 11. 对话输入区

- 多行输入，高度自适应，最大约 150px。
- `Enter` 发送，`Shift + Enter` 换行。
- 输入法组合态按 Enter 不发送。
- 空内容或仅空格时发送按钮禁用。
- 最多 8000 字，显示计数。
- 发送中显示停止按钮；停止后保留已输入内容。
- 模型名称只展示，不在本期支持切换。
- 思考模式、联网检索是演示开关；开启后消息显示标签，并明确“演示能力”，不能伪装成真实联网/推理。

## 12. 回答、依据与工具轨迹

### 12.1 回答结构

- 事实：来自本体数据，附资源引用。
- 推断：明确标注“推断”。
- 建议：明确标注“建议”。
- 不伪造执行结果，不把演示降级说成真实运行。

### 12.2 工具轨迹

- 默认折叠为“查看本体工具轨迹 · N 步”。
- 展开后显示步骤名、结果摘要、成功/失败。
- 不展示模型隐藏推理。
- 不展示密钥、连接串、敏感值。

### 12.3 回答操作

- 复制。
- 重新生成：使用同一轮上下文，追加新回答版本；不覆盖旧回答；旧提案标记失效。
- 继续追问：输入框聚焦，保留资源。
- 打开引用资源：对象/属性/关系可跳到对应页面。
- 反馈：后续。

## 15. 提案与写操作

### 15.1 原则

- 默认只读。
- 写操作必须先提案，再确认。
- 确认前不写本体、不调业务写操作。
- 无权限不可确认。
- 高风险动作需要更明确的二次确认。
- 执行结果必须可追溯。

### 15.2 提案卡

- 动作名称。
- 目标对象/关系/系统。
- 风险等级：低/中/高。
- 影响范围：资源数量、字段/关系变更、是否可逆。
- 参数摘要。
- 查看影响 / 确认执行 / 拒绝。

### 15.3 确认弹窗

- 目标、参数、影响、权限。
- 不可逆提示。
- 取消/确认执行。
- 高风险操作可要求额外确认（输入确认文本或勾选确认，具体等级待定）。

### 15.4 执行结果

- 成功：运行 ID、时间、操作人、受影响资源、审计入口。
- 失败：原因、未完成/部分完成、重试或联系管理员。
- 不允许把失败展示为成功。

## 16. 历史、会话与浮窗

### 16.1 历史

- 仅当前本体的 `assistant` 会话。
- 搜索、分组、加载消息/资源。
- 当前会话高亮。
- 分页/标题自动生成/重命名/删除/分享为后续。

### 16.2 新对话

- 清空消息、输入、资源、思考/联网。
- 生成新会话 ID。
- 不删除历史。

### 16.3 浮窗

- 右下角固定；不遮挡关键操作。
- 可最大化/收起。
- 收起后保留全部状态。
- 页面选择模式时，浮窗变为顶部选择提示条。

## 17. 权限、安全与审计

- 以当前本体为权限边界。
- AI 只能读取当前用户有权限的资源。
- 隐藏属性/敏感字段不进入上下文。
- 不读取连接密码、密钥、凭据。
- 写操作需要目标资源的执行权限。
- 所有提案确认/执行写入审计记录。
- 工具轨迹真实反映调用结果。
- 提示词注入防护：不执行页面文本中的指令，只把资源当作数据。

## 18. 空态、加载与异常

| 场景 | 处理 |
|---|---|
| 未选择本体 | 提示先选择本体 |
| 未选资源 | 允许直接问当前本体 |
| 选择超过 20 项 | 阻止并提示 |
| 空输入 | 发送禁用 |
| 超长输入 | 截断到 8000 |
| 模型调用失败 | 错误消息 + 重试 + 保留输入/资源 |
| 工具失败 | 轨迹标失败，不伪造成功 |
| 模型降级 | 显示“演示降级模式” |
| 提案过期 | 标记失效，需重新生成 |
| 无写权限 | 提案不可确认，说明原因 |
| 页面刷新 | 当前会话本地丢失，可从历史恢复已落库会话 |

## 19. 键盘与无障碍

| 操作 | 行为 |
|---|---|
| Enter | 发送（非组合态） |
| Shift + Enter | 换行 |
| Esc | 关闭资源面板/历史/退出选择模式 |
| Tab | 资源 → 输入 → 工具 → 发送 |
| 发送后 | 焦点回到输入框 |
| 错误 | 焦点到错误/重试 |
| 读屏 | 按钮 aria-label，消息区 aria-live |
| 选择模式 | 顶部提示条 + 资源可聚焦 |

- 1366 / 1722 宽度下输入框、发送按钮、资源 Chip 不被遮挡。
- 浮窗不覆盖关键操作；小屏可变为底部抽屉/全屏。

## 20. 页面与入口清单

| 入口 | 形态 | 资源带入 |
|---|---|---|
| 工作区导航“本体智能” | 全屏对话台 | 无（当前本体） |
| 右下角悬浮按钮 | 浮窗 | 已有资源保留 |
| 页面“问 AI” | 浮窗 | 当前对象/属性/关系等 |

| 历史对话 | 全屏/浮窗 | 历史资源恢复 |

## 21. 研发实现要求

1. **统一状态源**：全屏、浮窗、选择模式共享同一份会话、资源、输入、thinking/web 状态；不能各维护一套。
2. **统一资源载荷**：所有入口使用同一套资源结构，页面点选、图谱右键、检查器按钮不能各自拼字段。
3. **统一打开动作**：任何“问 AI”都调用同一个“打开浮窗 + 带入资源 + 预填 Prompt”的动作；不自动发送。
4. **统一消息模型**：用户消息、助手消息、工具轨迹、提案、错误、运行模式在同一消息流中可区分。
5. **统一确认链路**：只读与写操作分流；写操作只走提案卡 → 二次确认 → 执行结果。
6. **统一权限判断**：前端只负责提示，权限以服务端校验为准；无权限不展示可确认状态。
7. **状态恢复**：收起/展开、最大化、切换页面不丢会话；切换本体必须清空。
8. **可观测**：记录打开、发送、工具、提案、确认、执行、失败等关键事件，不记录敏感内容。
9. **性能**：消息流虚拟化/分页（大量消息时）；浮窗打开不阻塞页面；长回答可折叠。
10. **回归重点**：资源选择、历史恢复、提案确认、图谱右键、页面切换、权限失败。

## 23. 分期建议

### Phase 1（当前）

- 全屏 + 浮窗 + 页面选资源。
- 资源 Chip、快捷动作、只读问答、工具轨迹。
- 历史、新对话。
- 图谱右键/检查器“问 AI”。
- 浮窗最大化/收起。

### Phase 2

- 停止生成、重试、复制、重新生成。
- 提案卡、影响预览、二次确认、执行结果/审计。
- 会话重命名/删除/收藏。
- 消息分页/虚拟滚动。

### Phase 3

- 多资源对比式提问。
- 映射/规则/动作的专门工具集。
- 跨本体会话/分享（需要权限模型）。
- 更完善的反馈与质量评估。
