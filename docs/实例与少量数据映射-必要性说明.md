# 关于“实例是否需要继续做”的说明

> 用途：下周开发任务评审 / 向领导说明
> 日期：2026-10-23
> 结论先行：**不建议现在做完整的“实例管理平台”，但必须做一个最小“实例样本层”。否则本体映射只能算配置，不能算验证；语义查询只能解释模型，不能证明业务场景跑得通。**

## 一、先把“实例”拆成两件事

| 概念 | 是什么 | 本期建议 |
|---|---|---|
| 实例管理平台 | 实例的增删改查、导入导出、同步、权限、实例详情页、实例关系页 | **不做**，至少本期不做完整菜单 |
| 实例样本层 | 每张核心表保留少量脱敏样本行，供映射校验、治理规则、场景验证、语义查询取证 | **必须做最小版** |

领导担心的“实例开发要不要继续”，如果指的是完整实例管理平台，我同意可以缓。
但如果连**少量样本数据**都没有，本体的映射、治理和场景验证会停留在“纸面建模”。

## 二、没有实例，哪些事情做不了

| 工作 | 没有实例时能做到什么 | 没有实例时做不到什么 |
|---|---|---|
| 字段映射 | 能配置“源字段 → 对象属性” | 不能验证主外键能不能关联、空值率、枚举覆盖、重复键、类型转换 |
| 关系映射 | 能画出对象 A → 对象 B | 不能验证真实数据里到底是一对一、一对多还是多对多，是否存在孤儿记录 |
| 本体治理 | 能做命名、主键、结构完整性检查 | 不能做数据完整性、唯一性、引用完整性、枚举合规、口径一致性检查 |
| 业务场景验证 | 能列出场景需要哪些对象、关系、规则 | 不能回答“这个场景有没有数据、能不能跑通、结果对不对” |
| 语义查询智能体 | 能解释本体里有什么对象、关系、规则 | 不能证明“按这个场景查，能查到业务结果”；只能做本体说明，不是业务查询 |
| 评审演示 | 能展示模型结构 | 演示时页面是空的，无法让业务方确认“这就是我们要的数据” |

一句话：**结构可以没有数据，但验证不能没有数据。**

## 三、为什么“少量数据映射”也必须有一张表

“少量数据映射”不是把数据放在前端，也不是每次临时查客户生产库。它需要后端有一个稳定的落点：

1. **映射校验要可重复**
   - 同一个映射，今天验证通过，明天还要能复现。
   - 每次都直连客户库，会受网络、账号、权限、库表变更影响，结论不可复现。

2. **语义查询要可解释**
   - 智能体回答“这个场景能查到 37 条付款申请”，必须基于一份确定的样本快照。
   - 没有快照，回答只能靠模型猜，或者每次现查生产库，风险和性能都不可控。

3. **治理规则要能跑**
   - 唯一性、非空、枚举、外键存在性这些规则，本质是对数据跑 SQL/校验。
   - 没有样本表，规则只能“保存”，不能“执行”和“验证”。

4. **演示和评审要稳定**
   - 客户现场网络不可控，不能依赖实时连客户库。
   - 平台内保存少量脱敏样本，才能离线演示、稳定复现。

所以：**就算不做实例菜单页面，后端也必须有一张实例样本表 + 只读 API。** 页面可以没有，存储和接口不能没有。

## 四、最小方案：不做实例平台，只做“场景验证样本”

建议本期只做四件事：

1. **一张通用实例样本表**
   - `ontology_id`
   - `object_type_id`
   - `instance_key`（业务主键）
   - `data_json`（脱敏后的字段值）
   - `source_code / source_table / source_pk`
   - `sample_batch / sampled_at / is_masked`

2. **一个只读实例 API**
   - 按对象类型查样本
   - 按主键查单条
   - 按场景资源集合批量取样本
   - 只读，不提供新增/编辑/删除

3. **一个内部样本导入脚本/接口**
   - 从 CSV/Excel 或客户表导出文件导入
   - 每张核心表 100～1000 行，或 1%～5% 采样
   - 必须脱敏；不接生产库实时查询
   - 优先覆盖主键、外键、枚举、空值、边界值

4. **两个使用场景**
   - 数据映射页：显示源字段样例值、连接成功率、空值率、重复键提示
   - 语义查询/场景验证：只读样本 + 本体语义，返回“有没有数据、大概多少、能否跑通”

这套东西的工程量远小于完整实例平台，但能直接支撑下周的映射图谱、治理技能和语义查询验证。

## 五、关于“语义查询肯定不碰数据”

这句话要分两种模式看，建议在评审时明确：

| 模式 | 是否读数据 | 能回答什么 | 本期定位 |
|---|---|---|---|
| 语义解释模式 | 不读 | 本体里有哪些对象、属性、关系、规则；某个对象怎么定义 | 可以先做，不依赖实例 |
| 场景验证模式 | 只读脱敏样本 | 这个场景需要哪些资源、有没有数据、关联是否成立、样例结果是什么 | 需要最小实例样本层 |

这样既尊重“语义查询不碰生产数据”的原则，又能让业务场景验证落地。
我们不是要接生产库，而是用**平台内脱敏样本**做验证，风险可控。

## 六、对下周任务的直接影响

| 下周任务 | 是否依赖实例样本 | 说明 |
|---|---|---|
| 1. 数据映射页面优化 + 映射图谱 | **强依赖** | 没有样本，图谱只能画线，不能验证映射是否成立 |
| 2. 本体智能的操作 | 弱依赖 | 可以先做交互和语义解释；场景验证需要样本 |
| 3. 本体部分流程适配动态表单 | 不依赖 | 可并行 |
| 4. 本体图谱细节优化 | 不依赖 | 可并行 |
| 5. 本体治理技能实现（wb） | **强依赖** | 规则要拿样本跑，否则只能保存不能验证 |
| 6. 本体语义查询（李阳） | 分模式 | 语义解释不依赖；场景查询/验证依赖 |

建议排期：

```text
第 1～2 天：实例样本表 + 只读 API + 样本导入（不做菜单）
第 2～5 天：映射图谱用样本做字段预览与关联校验
并行：智能体交互、动态表单、图谱细节
第 5 天起：治理技能用样本跑规则；语义查询先做语义解释模式
```

## 七、需要领导拍板的三件事

1. **是否批准“最小实例样本层”**：一张表 + 只读 API + 内部导入，不做实例菜单。
2. **是否同意样本数据脱敏后存放在平台内**，而不是每次实时查客户生产库。
3. **是否同意本期只选 1～3 个业务场景、5～10 张核心表做样本**，不追求全量实例。

## 八、给领导的一段话（可直接转发）

> 我们不是要重启一个完整的实例管理平台。现在建议做的是一个最小的“实例样本层”：后端保留一张样本表、一个只读 API、一个内部导入脚本，不做实例菜单页面。  
> 原因是，本体映射和治理如果只有结构没有数据，只能“配置”，不能“验证”：主外键能不能关联、有没有孤儿记录、枚举是否覆盖、场景能不能跑通，这些都必须拿少量脱敏样本跑一遍。语义查询的“语义解释”可以不碰数据，但“场景验证”必须读平台内的脱敏样本，不能靠模型猜。  
> 这部分工程量很小，但能直接决定下周映射图谱、治理技能和语义查询是“演示”还是“可验证”。建议批准最小样本层，范围控制在 1～3 个场景、5～10 张核心表。
