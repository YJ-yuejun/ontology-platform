# 实例工作台：产品交互与验收记录

日期：2026-10-29。名称保持“实例”。

## 验收范围

用户目标是按照 Palantir 的交互细节深化实例功能，兼容不同页面尺寸，并指出对象与属性设计对实例操作的影响。用户随后明确：“我们现在是产品原型制作阶段，按照原型来做就行”。本次交付为可实际操作、可供研发评审的产品原型。

用户已确定商用身份方案为接入现有平台统一登录与权限，接口由研发提供。真实身份服务、生产负载、部署运维和外部系统 Action 回写作为研发接入项，本次不将演示身份或本地维护表述为已接通生产能力。

## 回归结果

- 前端：`npm run build` 成功；`npm test` 全部 68 项通过（包含 10 项实例表格/数据契约回归）。
- 后端：`.venv/bin/python -m unittest discover -s tests -q` 全部 71 项通过；新增 9 项实例、关系与接口契约测试，数据写入使用隔离临时数据库。
- UI 写入验证使用 127.0.0.1:8022 的独立临时数据库，不把临时样例加入用户的本地工作数据。
- 构建保留既有 bundle 超过 500 kB 的提示；代码拆分及生产性能由研发集成阶段处理。

## 对象与属性模型调整建议

| 问题及证据 | 建议怎么改 | 本次处理 |
|---|---|---|
| 管网 9 类对象当前标题均使用主键，例如 Equipment.equipmentId、Customer.customerId | 有业务名称时将 title_property 指向名称，例如 equipmentName；定义空名称回退为编号。切换前检查现有实例是否有名称值 | 保留历史数据；有合理标题属性时表单直接复用，避免重复输入；其余使用独立展示标题并提示建议 |
| 管段 pressure 为“实时属性”且 is_required=true，手工新建没有值的生成来源 | 区分“新建必填”与“同步后质量非空”；可增加 required_on_create 或把同步后非空放入质量规则。实时值由映射/计算产生 | 提前展示配置原因；不提供伪造实时值的输入，也不静默取消标准约束 |
| 历史实例 record_status 存在“运行/执行中”等业务状态 | 对象生命周期使用 state_property（例如 status）；记录管理状态独立限定有效/冻结/历史。历史数据迁移需明确对照、评审并保留原值 | 表头和表单改叫“记录状态”；不覆盖导入的历史状态；业务状态仍按对象属性展示 |
| 属性类别目前兼任编辑控制 | 建议补充 edit_mode（只读/手工/Action）、edit_action_id、计算来源与创建默认值；避免仅靠类别或页面按钮控制写入 | 原型中计算/实时属性只读，其余使用本地实例维护；真实 Action 绑定由研发接入 |
| 类型只定义 decimal/datetime，未完整定义显示与存储契约 | 数值补 precision/scale/单位与舍入规则；日期补日期/时间、时区和显示格式；金额生产存储使用约定的定点精度 | 不再统一截断为两位小数；提供日期控件，保留未修改的已有时间值；不能用原型浮点表示替代财务精度验收 |
| 模板“单位/枚举”可能混在同一单元格 | 枚举的 options 与计量单位 unit 分别存储，枚举不显示成“单位：运行/停止…” | 表单对枚举和布尔不输出误导的单位提示；保留模板来源信息 |
| 关系上可能有金额、比例、生效期 | 简单关系保留关系属性；若有独立审批、生命周期或复杂多方关联，升为明细对象 | 可编辑和查看关系属性，并按关系基数及端点定义校验 |

## 研发接入边界

1. 统一登录身份校验、对象/属性/数据范围与 Action 权限的服务端强制执行。
2. 属性编辑与企业受控 Action、审批、幂等、失败补偿和外部回写的绑定。
3. 大规模对象查询、游标或服务端分页、批量导出、统计与关系索引。
4. 生产数据版本、备份恢复、安全、负载和可观测性验收。
