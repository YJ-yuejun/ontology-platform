# v1.9 产品决策与数据保护

## 一、最终概念结构

```text
本体
  ├─ 业务域
  │    └─ 主题域
  │          └─ 对象类型
  ├─ 接口
  ├─ 关系类型
  ├─ 规则 / 函数 / Action
  ├─ 数据源 / 映射 / 实例
  └─ 业务场景 / 权限 / 版本 / 审计
```

这条结构同时满足企业数据治理的 L1/L2 分类习惯和 Foundry 式运行语义：

- 业务域、主题域用于稳定分类；
- 对象、属性、关系描述业务事实；
- 接口描述多个对象共同遵守的结构契约；
- 规则和 Action 让本体可以参与判断与执行；
- 业务场景横向编排多个对象与能力，不属于分类树。

## 二、本轮取舍

### 1. 去掉对象类型组

对象类型组与业务域、主题域存在明显重复，容易出现一个对象到底“属于哪个层级”的争议。v1.9 中对象直接归属主题域，主题域归属业务域。

旧包中的分组数据可被兼容读取，但不会进入新产品页面、接口、导出包或发布检查。

### 2. 去掉共享属性

共享属性会引入“集中修改是否影响所有对象”“对象能否覆盖类型”等额外治理问题。当前阶段没有足够明确的跨域复用诉求，因此属性在对象或接口中显式定义。

如果未来确实需要统一审计字段，可通过接口契约实现；接口变更仍需生成受影响对象清单和版本变更。

### 3. 接口保持独立

接口不是业务对象，也不产生实例。它定义多个对象共同满足的属性契约，例如“可审计”“可分派”。

对象实现接口时：

1. 用户从接口列表中选择；
2. 前端补齐缺失的契约属性；
3. 后端保存时校验属性是否存在且类型一致；
4. 发布前再次检查接口完整性；
5. 接口仍被对象实现时禁止删除。

v1.9 不提供对象父类继承。若未来需要“合同继承文档”这类业务分类继承，应先单独评审多继承、属性冲突、行为继承和版本兼容性，不与接口机制混为一谈。

### 4. 去掉复数显示名称

复数显示名称主要解决英文 UI 的单复数变化，例如 `Contract / Contracts`。中文菜单和列表通常都显示“合同”，单独维护该字段会增加无业务价值的数据。新建和编辑对象不再展示该字段，保存时固定为空；数据库列只为旧数据兼容保留。

### 5. 数据源必须先登记再引用

对象页面只选择已登记数据源编码，不直接输入任意字符串。数据源页面负责连接元数据；映射页面负责物理表、字段和关联键到对象、属性或关系的绑定。

生产实现中应进一步增加：连接测试、凭据托管、字段发现、样例预览、主键覆盖率、关系匹配率、同步策略和数据质量门禁。

### 6. 业务场景必须可执行、可验收

业务场景至少包含：

- 业务目标、入口对象；
- 触发方式与触发条件；
- 关联对象和关系路径；
- 所需数据源；
- 规则、Action；
- 参与角色和责任人；
- 业务输出或对象状态变化；
- 可验证的验收口径。

后端会检查入口对象和所有引用是否存在，并保证所选关系的两端对象都在场景中。场景运行会产出对象定位、关系穿透、规则执行和 Action 确认轨迹。

### 7. 用户不直接编辑 JSON

JSON 仍可以作为 API 与 SQLite 的内部存储格式，但不作为业务用户的默认交互：

- 枚举字段使用下拉选择；
- 对象、关系、规则、Action、接口和数据源使用资源选择器；
- 参数与结果映射使用键值表格；
- 测试样例使用结构化记录编辑器；
- 文件导入保留 JSON 包兼容，但属于文件交换而非手工录入。

## 四、两个内置本体的保留策略

只保留：

- `enterprise.supplychain.manual`：采购与财务协同本体；
- `enterprise.pipeline.operations.manual`：管道运输运营本体。

v1.9 的一次性清理会删除历史资产、客户服务等内置演示本体，但不会删除之后由用户创建的新本体。

## 五、治理状态机

```text
设计中
  └─ 校验通过 → 待评审
                  └─ 评审通过
                       └─ 发布 → 已发布不可变版本
                                    └─ 再次编辑 → 新工作状态
```

变更日志记录具体资源的增删改和修改前后快照；发布记录汇总版本、兼容性、变更原因、评审人和完整快照。两者职责不同，不合并为一张事实表。

## 六、智能构建约束

智能构建可以创建新本体，也可以基于已发布版本更新现有本体。无论哪种模式，模型输出都必须先成为 Proposal：

```text
Evidence → 多轮抽取与对齐 → Proposal → 人工决策 → Working State
         → 确定性检查 → 评审 → 发布
```

模型不得直接写正式本体；主键、引用、类型、权限、版本、Action 安全和正式写入由平台控制。生产环境还需要模型评测、证据定位、提示词版本、重放、成本限额和本地模型替换能力。
