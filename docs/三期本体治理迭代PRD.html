ONTOLOGY CENTER · PHASE 3

本体治理三期迭代 PRD

目标是让语义模型从“能建”进入“能检查、能追溯、能比较、能安全发布”。本文只定义业务逻辑、页面与验收重点，不展开物理表设计。

1. 本期范围与优先级

P0 · 发布版本闭环工作状态变更 → 本体质检 → 提交评审 → 评审通过 → 发布不可变版本；发布前二次校验模型未变化。
P0 · 历史版与差异每次发布保存语义模型快照；旧版只读；能比较两个发布版，或发布版与当前工作状态；删除资源在旧版仍可见。
P1 · 语义治理工具映射图谱展示“物理来源 → 治理资产 → 本体语义”，并可切换已发布版本；字典管理维护建模下拉选项。
P1 · 可追溯记录在变更记录查看谁在何时对什么资源执行了什么操作；工作状态变更与发布版本记录相互关联。

2. 用户主流程

修改工作状态→查看影响并质检→提交评审→评审通过→发布新版本→查看／对比历史版
  • 用户编辑对象、关系、规则、动作、映射等语义资源时，只影响当前工作状态；任何修改都应留下操作记录。
  • 质检报告绑定一次具体的模型状态。报告生成后只要语义资源或共用字典发生变化，就显示“已过期”，必须重跑。
  • 阻断性错误未解决、没有待发布变更、质检未通过或报告过期时，不能提交评审。仅“评审通过”的工作状态可发布。
  • 发布时再次核对工作状态和质检指纹；若期间被修改，拒绝发布并让用户重新质检和评审。
  • 正式版本仅记录语义定义与治理配置，不把实例业务数据、密码、密钥作为版本快照内容。

当前交付边界：本期为“一个工作状态 + 多个只读发布快照”。它借鉴 Foundry 的变更评审和发布思路，但不宣称已实现多用户并行分支、rebase、自动合并或冲突裁决；这些能力须单独规划和验收。正式系统还需接入登录身份与评审权限，原型中的评审按钮不等于已完成权限隔离。

3. 页面与交互重点

入口本期应完成的业务行为验收重点
本体质检对当前工作状态运行确定性语义检查，保存报告；对话仅用于解释报告和给出基于证据的修复指引。有结论、问题清单、检查范围、执行时间与报告过期提示；AI 不得擅自改分或声称检查了实例及生产接口。
版本与发布集中呈现待发布变更、模型检查、影响概览、质检门槛、评审状态和历史版本。不能绕过质检与评审直接发布；发布版不可编辑；每个历史版本可打开只读语义快照。
本体版本对比选择两个状态，按资源稳定标识比较新增、修改、删除，并在左右两栏看字段差异。删除项在旧版仍有定义；对话只能解释已算出的差异，不把“可能影响”冒充已验证结果。
映射图谱由已有来源、治理资产、语义映射推导三层血缘；可选择当前工作状态或历史发布版。节点和连线有登记依据；不凭空造映射；旧物理直连以待适配样式区分。
字典管理集中维护共用建模选项，并让表单使用同一套可选值。业务域、主题域不是字典项；已被引用的选项不可随意删除；字典变化使旧质检报告过期。
变更记录查看操作者、时间、操作、资源与所属本体；支持筛选和分页。记录可追溯；系统初始化记录与人工操作区分；不将操作日志当成历史版本快照。真实用户身份由平台鉴权接入，原型暂以建模管理员标识演示。

4. 菜单结构

按 Ontology Manager 常见的“发现模型—编辑语义资源—处理映射和运行能力—治理变更”任务路径组织，但保留本产品已有业务域、主题域、规则、字典等菜单：

发现本体工作台、模型图谱、业务场景
本体模型业务域与主题域、对象类型、关系类型、动作类型、规则、接口、字典管理
数据与映射数据源与映射（含映射图谱）、实例数据
运行能力系统能力与执行映射、本体智能体
变更与发布本体质检、本体版本对比、版本与发布、变更记录、权限策略

不为“映射图谱”单独复制一套配置：它是数据源与映射的只读可视化视图。历史版入口放在版本与发布的发布记录中。

5. 版本业务规则

  1. “本体 ID”代表长期稳定的语义空间；“版本号”只代表一次正式发布，不随着普通保存自动增加。
  2. 发布 V1.1 后，V1.0 的语义定义保持发布当时的样子。V1.1 删除的资源，在 V1.0 中仍可查看，在 V1.1 中不存在。
  3. 当前建模页面默认读工作状态；历史版查看与版本对比显式选择发布快照。不能把一个页面里的历史只读值伪装成可编辑的当前值。
  4. 字典属于跨本体共用配置；每个发布快照保留当时用于解释模型的字典值。字典变更可以使工作状态质检过期，但不会改写已发布快照。
  5. 发布影响中的“兼容、增量、破坏性”是建模层预判；若未完成下游依赖或生产数据验证，必须明确标为待核查。

6. 明确不纳入本期

不做实例数据版本化、历史实例回放、数据源生产连通性背书、自动数据迁移、自动回滚、多并行工作分支与智能冲突合并。若后续需要“恢复旧版”，应由旧版定义生成一份新的待评审工作变更，再走质检和发布流程，不直接覆盖历史。

7. 验收用例

  • 创建资源后不运行质检：无法提交评审和发布；运行通过后可提交并审批。
  • 质检通过后再改对象属性或字典项：报告显示过期，发布被阻断。
  • 发布 V1.0 后删除对象并发布 V1.1：V1.0 只读页仍有对象；版本对比显示“删除”。
  • 映射图谱切换 V1.0 与 V1.1：图中节点与连线按所选快照变化，不显示敏感连接凭据。
  • 用户可在变更记录按时间追踪“谁修改了什么”，并从发布记录打开对应历史语义模型。
