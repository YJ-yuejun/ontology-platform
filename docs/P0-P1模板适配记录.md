# P0/P1 前端原型模板适配记录

版本：v1.10（2026-09-08）

## 适配原则

本轮以《本体建模模板.xlsx》的 15 个 Sheet 为字段和事实来源。P0/P1 交互建议只有在不改变模板语义的前提下才落地；如果产品建议与模板字段冲突，以模板为准，并通过平台字段或帮助说明承接差异。

## 已完成的改造

| 范围 | 改造 | 模板字段如何保留 |
|---|---|---|
| 对象类型 | 四步向导：对象身份、业务分类、属性结构、接口与映射 | 保留对象类型 ID、对象类别、业务域、业务定义、主键、生命周期、状态属性、负责人、来源系统、核心对象、事件对象、需要行动、建模状态、版本语义；平台稳定标识单独保留 |
| 对象类别 | 没有删除“对象分类” | 下拉首选模板的业务实体、业务任务、物理资产、业务事件；历史导入值不静默转换 |
| 对象属性 | 增加模板字段折叠区 | 属性类别、数据类型、单位/枚举、业务定义、必填、唯一、来源系统、来源字段、更新频率、转换规则、质量要求、状态、版本均可承接；来源字段仍可查看/填写，但真实接入建议在数据映射页配置 |
| 业务场景 | 将资源选择区改为模板语义字段 | “主要对象、关键关系、业务规则/判断、业务行动、输入数据、关联系统、输出/状态变化”均有对应入口；场景步骤仍是平台为可运行闭环增加的结构化执行扩展 |
| 关系 | 补齐模板关系字段 | 关系 ID、关系名称、关系 API 名称、起点/终点、方向、基数、业务定义、来源、起点键、终点键、核心关系、双向展示、状态、版本 |
| 关系属性 | 保留但标为高级配置 | 不把关系属性误当对象属性；关系实例和关系映射仍按模板关系层治理 |

| Action 条件 | 显式配置 AND/OR | 模板“前置条件”原始表达式保留；结构化字段只辅助生成和校验，不执行任意 SQL |

## 有意保留的产品扩展

1. **主题域**：模板 02 表直接给出“业务域”，没有单独主题域列；平台仍保留“业务域 → 主题域 → 对象类型”的治理分层。模板业务域原值不被替换，主题域只作为平台分类扩展。
2. **平台资源状态**：模板“已确认/设计中”映射到 `design_status`；平台 `experimental/active/deprecated` 继续表示资源使用状态，不能把两套状态混为发布状态。
3. **稳定标识**：模板业务编号（如 `OBJ-001`、`L-001`、`A-001`）保留在外部 ID；平台 API 名称保留用于程序和 Agent 的稳定引用。
4. **接口菜单**：结构性“接口”仍作为独立资源，用于声明属性契约；模板“接口能力”在“系统能力与执行映射”管理，两者没有合并。
5. **映射数据源**：对象页面的“映射数据源”是已登记数据源的选择，不替代 07 数据映射中的来源表、来源字段、主键/关联键和转换质量规则。
6. **版本列**：模板各表的“版本”仍由本体工作状态与发布快照统一承接，页面不再让用户在每个资源上手工维护一套互相矛盾的版本号；发布时生成不可变版本记录，并保留变更对象与影响范围。

## 不在本轮强行改动的内容

- 模板已知的对象 ID/名称冲突、图谱边方向冲突和行动作用对象待确认问题继续作为证据问题保留，不能在页面上静默修正。
- 管网与采购财务内置本体、模板证据、实例和企业资源数据未删除或重建。
- 真实业务接口不会因原型填写而被调用；生产调用仍需执行网关、连接器、凭据、权限、审批、幂等、重试、补偿和审计能力。
- SQLite + JSON 仍是原型存储方案，生产落地需替换为版本化元数据和受治理连接器。
