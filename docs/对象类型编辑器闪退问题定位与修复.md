# 对象类型编辑器"闪退"问题：定位与修复

## 现象

编辑任意对象类型时，弹窗会**自己关掉、回到对象列表**，正在填写的 4 步表单内容全部丢失。用户描述为"闪退"，发生在「接口与检查」那一步尤其明显。

## 定位过程

一开始用 `element.click()` 做自动化复现，**始终无法触发**。原因是关键：`element.click()` 只派发 `click` 事件，**不派发 `mousedown`**；而这个 bug 的触发点恰好挂在 `mousedown` 上。改用 CDP `Input.dispatchMouseEvent` 派发真实鼠标事件后立刻复现。

## 根因

`frontend/src/components/Modal.jsx` 原先的遮罩关闭逻辑：

```jsx
<div className="modal-backdrop" onMouseDown={(event) => event.target === event.currentTarget && onClose()}>
```

只要 `mousedown` 落在遮罩上就立即关闭。而对象类型编辑器的布局是：

| 元素 | 水平范围 |
|---|---|
| 弹窗（`.modal-wide`） | x = 263 – 1223 |
| **「编辑」按钮（右侧 inspector）** | **x ≈ 1380** |

**「编辑」按钮落在弹窗右侧的遮罩区域上**。于是：

1. 第一次 `mousedown` + `mouseup` 打在「编辑」上 → 弹窗打开；
2. 若用户是**双击**（或连点、或稍慢的第二次点击），第二次 `mousedown` 落在 x=1380 —— 此时那里已经被弹窗遮罩覆盖 → **遮罩的 `onMouseDown` 立即把刚打开的弹窗关掉**。

因为「编辑」按钮永远在右侧 inspector 里、永远位于弹窗矩形之外，所以**任何对象类型都会复现**，与数据无关。

实测（1500×860 视口）：

| 场景 | 修复前 | 修复后 |
|---|---|---|
| 单击「编辑」 | 弹窗打开 ✅ | 弹窗打开 ✅ |
| **双击「编辑」** | 弹窗打开后**立刻关闭** ❌ | 仍打开 ✅ |
| 弹窗打开时点弹窗右侧空白 | **立刻关闭** ❌ | 仍打开 ✅ |
| 按 Esc | 关闭 | 关闭 ✅ |
| 点 X | 关闭 | 关闭 ✅ |
| 点「取消」 | 关闭 | 关闭 ✅ |
| **普通弹窗点遮罩**（如"新建业务域"） | 关闭 | **关闭 ✅（默认行为保留）** |

## 修复

`frontend/src/components/Modal.jsx`：遮罩关闭改为三个前提同时满足，缺一不可。

1. `closeOnBackdrop` 未被关闭；
2. 这次 `mousedown` **确实起始于遮罩本身**（用 `onMouseDown` 记标记、在 `onClick` 里校验），避免"从弹窗内部拖到外面松手"被误判为点击遮罩；
3. 弹窗已打开 **超过 300ms** —— 这条专门堵住"第二次点击紧跟在打开之后"的竞态。

同时新增 `closeOnBackdrop` 属性（默认 `true`，不改变其它弹窗行为），并对**多步表单**显式关闭遮罩关闭：

- `pages/ObjectTypes.jsx` → `closeOnBackdrop={false}`（本次反馈的对象类型编辑器）
- `components/CreateOntologyWizard.jsx` → `closeOnBackdrop={false}`（同为多步向导）

理由：多步表单里一次误点就丢掉全部草稿，代价远大于"点外面关闭"的便利；弹窗仍保留 X 和「取消」两个明确出口，Esc 也仍然可用。

## 影响范围

`Modal.jsx` 在**三份副本中完全一致**，因此该缺陷在 `~/Documents/智能体平台/ontology-studio-manual`（用户实际访问的 `:8021`）上同样存在，修复可直接移植——`Modal.jsx` 与该副本无其它冲突。

其余 14 处 `<Modal>` 用法中，单步编辑弹窗仍保留"点遮罩关闭"的默认行为（符合常规交互）。如果希望所有编辑弹窗都防误关，可以统一改为 `closeOnBackdrop={false}`，但那是产品取舍，不是缺陷。
