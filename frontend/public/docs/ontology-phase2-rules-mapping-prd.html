1. 本期边界

本期将源系统结构转为可审查的本体语义：登记来源、获取表结构、设计映射、定义规则与函数，再进入已有的工作状态和版本评审流程。

来源登记→连接／导入结构→属性与关系映射→规则／函数定义→静态校验与评审

本期不读取业务记录，不做实例同步，不运行规则或 Action。“连接检查通过”只表示当时可读取元数据；“模型已发布”只表示语义定义已批准。

2. 数据源

2.1 页面与交互

“数据源与映射”为一个菜单、两个 TAB。数据源 TAB 采用左侧目录和右侧常驻详情，支持搜索、分页；点击行后在当前页面切换详情。顶部只保留 TAB、说明入口和当前 TAB 的新建按钮。

步骤前端交互后端责任
登记来源严格填写模板 06 的九个字段：数据源ID、系统名称、系统类型、数据库/接口/文件、数据主题、更新频率、数据范围、数据类别、接口方式。新建时九项齐全；编辑已有演示记录时可逐步补齐。原值原样保存；编码建立后不可改。模板下方的字段说明不作为数据源记录。
关联主题域可选的本体治理归类，独立于模板中的“数据主题”。保存主题域编码；不得覆盖数据主题原文。
配置 MySQL选择驱动后显示主机、端口、库名、用户名、密码。编辑时密码不回显，留空表示沿用。将连接元数据与来源关联；密码单独加密保存，不进入资源 JSON、导出文件或响应。
测试连接展示通过／失败和时间；更改地址、身份或密码后旧结果失效。使用所存凭据建立有时限的连接，查询元数据可见性；只以实际检查结果表示已连接。
选择来源表浏览授权可见的表／视图，勾选要采集的表，再点击“获取结构”。只读取选中表的字段、类型、注释、主键／唯一键、外键，保存结构快照。
离线导入上传 CSV 数据字典、JSON 结构或 MySQL CREATE TABLE 的 SQL 文件。解析并保存结构快照；SQL 文件只解析、不执行。

2.2 字段与来源规则

字段组规则说明
模板九字段新建必填，编辑保留原值下拉建议允许自由填写，必须容纳“实时/日”“秒级”“接口/数据库”“实时接口”等模板原值，不强制改写为产品枚举。
主题域关联可选扩展是本体分类引用，不是模板“数据主题”。
驱动、主机、端口、库、用户选 MySQL 时必填连接配置是技术扩展，不属于模板事实；接口和实时来源可先登记、后补连接器或离线结构。
密码首次连库必填后端只保存加密密文，前端不回显。
结构快照映射校验时需要无快照仍能保存草稿；不得声称已打通数据。
负责人、状态与演示来源不伪装成模板字段模板 06 无负责人或连接状态；清理历史“示例负责人”和虚假的 connected。采购财务内置来源标为演示登记。

运行环境必须安装 pymysql 和 cryptography。本地原型使用独立的受保护密钥文件；正式部署应接入企业凭据服务。服务账号应由实施团队按元数据读取所需权限配置。

3. 数据映射

3.1 页面与表单

映射 TAB 采用左侧目录和右侧常驻详情，按来源、目标和映射类型检索。列表将“本体对象/关系”与“本体属性”拆成两列；关系映射的本体属性显示为不适用。点击左侧记录即在右侧切换详情，不弹出侧边卡片；从数据源详情进入时自动带入来源筛选。来源表／字段优先从最近一次结构快照选择。

映射类型必须配置表单行为
属性映射数据源、来源表及字段、主键、目标对象及属性、负责人和状态目标属性只显示目标对象拥有的属性；原模板“对象属性”规范为产品“属性映射”，保留原值溯源。
关系映射数据源、来源表及字段、关联键、目标关系、负责人和状态本体属性为不适用；原模板“对象关系”规范为产品“关系映射”，保留原值溯源。

不提供第三种“对象映射”。历史采购财务演示资源转为主键属性映射，原编码为兼容引用保留。模板 07 的 14 项在右侧完整展示并可编辑，包括映射方式、转换规则、质量校验、更新方式、负责人和状态；实际转换、同步与数据质量统计进入下一阶段。

3.2 “校验映射配置”

原“映射样例测试”由静态校验替代。输入为映射、当前本体模型及结构快照；不需要输入一条业务记录。

检查项判定
来源资源数据源、表、字段或来源键是否存在。
目标资源对象、属性或关系是否存在，属性是否确属对象。
字段类型明显不兼容的类型给警告；单位、枚举或转换仍需人工确认。
主键约束检查物理结构是否声明主键或唯一键；未声明只提示待验证，不声称实际唯一。
转换设计选了表达式或字典映射，却未提供对应配置时提示警告。

响应仅有 valid、pending、error 以及逐项 ok/warning/pending/error。前端展示检查时间、模型修改时间和快照 ID；模型、映射或快照变化后重新检查。不得展示虚构的“匹配率”。

4. 规则与函数

页面展示模板 08 的全部四条示例，包括 R-001、R-002 和 F-001、F-002。“类型”取值为规则／函数；取消额外的“规则类别”和处置等级等基础表单字段。

4.1 新建与编辑

模板字段前端交互后端约束
逻辑 ID、类型、名称先选规则／函数；系统生成 R/F 编码，名称必填。编码在本体内唯一，导入原编号保留。
适用对象对象类型多选，至少一项。所有引用必须属于当前本体。
输入对象／数据、输入属性对象和属性选择；关系路径或外部数据可补充文字说明。结构化属性必须真实属于所选对象；保留模板原文和来源记录。
判断／计算逻辑、输出必填业务描述。输出可以是布尔、等级、原因或对象集合。原文可存草稿；不能自动宣称已有可执行实现。
触发方式、实时性、可复用、负责人下拉、勾选或人员填写。作为业务要求持久化；不启动定时或事件执行器。
状态、版本详情可查看；普通表单不任意填写正式版本。使用已有工作状态、评审和版本机制。

模板原行、来源行号、原始版本等导入信息不得因编辑被静默丢弃。旧业务规则资源可暂时保留供兼容读取；统一规则／函数页面以逻辑定义资源展示和编辑。

4.2 暂不开放的运行交互

样例测试、表达式执行和内置付款样例退出主界面。已有数据不删除。后续启用测试前，必须同时提供输入样例、可执行实现和预期输出；条件为假不能当作测试失败，函数的等级或对象集合不能按布尔值判断。

R-001 压力异常

需要进一步确认持续时间阈值、单位及取数窗口；二期先保存语义定义。

F-002 影响范围

需要确认遍历关系、方向、终止条件与任务状态过滤；二期先保存函数契约。

6. 验收清单

  1. “登记数据源”和“新建映射”按钮文字可见，且分别进入正确的新建表单。
  2. 不连接数据库可保存草稿；选择 MySQL 后填写连接参数，密码不在任何 GET 响应中出现。
  3. 连接检查失败能正确显示失败；成功后可浏览表、勾选表并生成结构快照。
  4. CSV／JSON／MySQL DDL 可形成结构快照；SQL 文件绝不执行。
  5. 映射只提供属性映射和关系映射；列表将“本体对象/关系”“本体属性”分列，M-001～M-004 与模板对应；静态校验能指出缺失源字段与目标资源，无快照时显示待验证。
  6. 规则页面能同时显示模板的两条规则和两条函数；新建和编辑不丢原模板信息。
  7. 规则表单保留模板 14 个业务字段的语义，适用对象支持多选，状态和版本交由治理流程管理。
  8. 页面不再展示伪“样例测试通过”“匹配率”或没有执行器的规则运行结论。
  9. 管网与采购财务内置本体及已有实例仍可读取；本轮不新增实例导入流程。
